# Combine the Assistant sidebars

Generated by Lazarus Project Assistant.

The Project Assistant currently splits chrome across two side panes. `ModeSidePanel` on the left holds Target, Mode, and the runtime plan and build stacks. `ConversationPanel` on the right holds history and the conversation list, separated from the chat by `ChatSplitter`. This change keeps Target and Mode at the top of the left pane, puts the rest on a two-page tab control under the mode combo, and gives the recovered right-pane width to the conversation.

The first page is History and receives every control that lives on the right sidebar today. The second page is Plan and receives every control that currently sits below the mode combo. The Plan page is disabled in Chat and Inspect. `ModeSplitter` stays so the combined sidebar can still be resized. `ConversationPanel` and `ChatSplitter` go away.

## 1. One sidebar under Mode

Target and Mode stay in `SidebarHeader`. A page control fills the rest of `ModeSidePanel`.

### 1.1 Add the page control under the mode combo

Status: complete

Stream a `TPageControl` named `SidebarPages` in `ProjectAssistantForm.lfm`, parented to `ModeSidePanel`, `Align = alClient`, so it sits under `SidebarHeader`. Add two sheets in that order: `HistorySheet` caption `History`, then `PlanSheet` caption `Plan`. Declare both the page control and the sheets in the unnamed first section of `TProjectAssistantForm`, with no `F` prefix and no trailing `Published` section. Default `ActivePage` is `HistorySheet`, because Chat is the usual first mode and the Plan page will be disabled there. Do not build this static frame in `FormCreate`.

### 1.2 Move the right-sidebar controls onto History

Status: complete

Move the streamed right-sidebar controls onto `HistorySheet` and retarget every `AnchorSide*` that names `ConversationPanel` to `HistorySheet`. Keep the current top-to-bottom order: History label, `HistoryCombo`, Export, Delete, Conversation label, `ConversationList`, `ConversationSearch`. Export stays left of Delete. The conversation list and search move with History because the right pane is removed and they have nowhere else to live. Wire `HistorySheet.OnResize` to `HistoryPanelResize`, and size the Export and Delete buttons from `HistorySheet.ClientWidth` instead of `ConversationPanel.ClientWidth`.

### 1.3 Reparent the plan and build stacks onto Plan

Status: not started

Parent the existing runtime `PlanPanel` and `BuildPanel` to `PlanSheet` instead of `ModeSidePanel`. Do not rebuild those button strips. On the Plan page the stacks stay in their current order: plan file list on top, build work tiles filling the rest. Plan buttons remain left to right: New Plan…, Open, Set Active, Refresh, Open Documents/. Build buttons remain left to right: Refresh, Open Plan, Start, Done, Reset, Work On This, Work On Plan. `EnsurePlanTabUi` and `EnsureBuildTabUi` must no longer require `ModeSidePanel` as the parent. `PinSidebarHeader` still keeps Target and Mode above the page control.

### 1.4 Remove the right sidebar and its splitter

Status: not started

Delete `ConversationPanel` and `ChatSplitter` from the `.lfm` and from `TProjectAssistantForm`. Update `TProjectAssistantForm.Resize` so the narrow-window squeeze uses only `ModeSidePanel` and `ModeSplitter`. It must not read the removed pane or splitter. The chat host stays `alClient` and gains the width the right pane used. Leave `ModeSplitter` between the combined sidebar and the chat.

## 2. Plan page follows mode

The Plan sheet is a place for plan and build work. Chat and Inspect do not use it.

### 2.1 Disable the Plan page in Chat and Inspect

Status: not started

In `UpdateModeSidePanels`, set `PlanSheet.Enabled` from `ActiveMode`. Chat and Inspect disable it. Plan and Build enable it. If the active page is `PlanSheet` when it becomes disabled, select `HistorySheet` first so the user is not left on a dead page. Do not force the Plan page open when entering Plan or Build. Call this from the existing `SyncModeUi` path so a mode combo change, a restored shell mode, and a locked send all agree. If a widgetset still allows a click on a disabled sheet, refuse that change and return to `HistorySheet`.

### 2.2 Keep the current stacks inside the Plan page

Status: not started

Do not show the plan file list in every mode. `PlanPanel` stays visible only in Plan mode. `BuildPanel` stays visible whenever the Plan page is enabled, which means Plan and Build only. Work tiles are no longer available in Chat or Inspect; that is the point of disabling the page. Button enablement already follows mode and send state and does not need a new rule.
