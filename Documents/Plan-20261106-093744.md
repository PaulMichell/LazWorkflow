## 1. Overview

Claude turns reach the IDE through `TAssistantToolBroker` (`Source/LazAssistantTools/AssistantToolBroker.pas`) over MCP. Grok turns use the native tool set in `Source/LazAssistantTools/AssistantTools.pas`. Running a plan on each backend showed that the broker is missing tools that plan items depend on, and that the broker's write tools cost far more tokens than the native ones. As a result, Claude plan runs leave items `blocked` and use several times the tokens. Evidence is in `Documents/Report-20261106-160000.md`.

This plan closes the gap. It is written to be run by **Grok**, through the native tools (`read_file`, `search_in_project`, `replace_in_file`, `run_compile`, `run_tests`, `run_git`).

Gaps found, from the tool lists in the two units:

| Need | Native (Grok) | Broker (Claude) |
|---|---|---|
| Change a few lines | `replace_in_file` | none; `replace_buffer` takes the whole file, and its reply echoes the whole file back |
| Compile a folder target | `run_compile` builds the packages under the folder | `lazarus_start_build` refuses: "Build input is missing or not a regular file" (`AssistantBuildJob.pas` ≈ 138) |
| Run tests | `run_tests` | `lazarus_start_tests` runs only a command set in Settings → Target tests |
| Search that sees open buffers | `search_in_project` | none; Claude Code's own `Grep` reads disk only |
| Form and `.lfm` edits | `ensure_form_component` | none |
| Delete, rename, add unit | `delete_path`, `rename_path`, `add_unit_to_project` | none |
| Plan registry | `list_plans`, `get_active_plan`, `set_active_plan` | none |
| Stage part of a file | not available on either backend | not available |

The plan-run prompt (`TProjectAssistantForm.BuildWorkPrompt`, `ProjectAssistantForm.pas` ≈ 3170) names the native tools on every backend, so a Claude turn is told to call tools it does not have.

### 2.2 Stop echoing whole files back
Status: complete

Files: `AssistantToolBroker.pas`, `AssistantIDEWorkspace.pas`, `Tests/AssistantMCPBridgeTest.lpr`.

Today `lazarus_replace_buffer` returns the whole new text, and so do `apply_changes`, `open_buffer` and `read_buffer`. A 47 KB file is sent back in full for a 20-line change. Changes:

- `replace_buffer`, `apply_changes` and `apply_local_rename` return the revision and the changed line ranges, not the text.
- `open_buffer` and `read_buffer` take an optional `include_text` (true by default, so current callers keep working). With `include_text:false` they return only the path, the revision and the line count. A caller that has already read the file in ranges through `lazarus_read_file` can then get a revision cheaply.
- Update the tool descriptions to say which tools return text and which do not.

Test: the replies of `replace_buffer` and `apply_changes` contain no buffer text, and the revision they return is accepted by a following `save_buffer`. `open_buffer` with `include_text:false` returns a revision that `replace_in_buffer` accepts.

### 3.3 Stage part of a file
Status: complete

Files: `AssistantToolBroker.pas`, `AssistantIDEWorkspace.pas`, `AssistantTools.pas`, `Tests/AssistantGitTest.lpr`.

Both backends can stage only whole files. When an earlier item left uncommitted edits in a file, a later item that touches the same file cannot be committed separately. Add a `stage_patch` tool to both backends: `lazarus_stage_patch` on the broker, and `stage_patch` in the native set. It takes a unified diff and works like this:

1. Check that every path in the diff is inside the target and is not under `.git`.
2. Run `git apply --cached --check`, and then `git apply --cached`. Never `git apply` without `--cached`, so the working tree is not touched.
3. Return the output of `git diff --cached --stat`.

It is a Build-mode tool and needs approval in Ask mode.

Test: in `AssistantGitTest`, in a temporary repository, check:

- a file with two separate hunks: staging one hunk leaves the other unstaged, and the commit contains only the staged hunk;
- a patch for a path outside the repository is refused;
- a patch that does not apply leaves the index unchanged.
