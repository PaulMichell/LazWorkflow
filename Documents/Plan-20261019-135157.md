# LazAssistantMonitor

Generated by Lazarus Project Assistant.

Implement the package specified in `Documents/Assistant Monitor Design.md`. That document is the contract for message names, error sentences, limits, and state transitions. This plan sequences the work and records the traps that are easy to get wrong. It does not replace the design.

The IDE remains the only process that talks to a model provider and the only process that runs tools. A paired client sends actions. The host streams the transcript, phase, status, plan list, and task list back. `Source/LazAssistantMonitor/` and `Source/KotlinMonitorApp/` already exist and are empty. Do not create a second tree.

Sections 2 to 7 are the Lazarus package and the dormant hooks it needs in LazAssistantTools. The package must compile and pass its console tests with the Android tree still empty. Sections 8 to 10 are the first client and the acceptance harness from the same design. They start only after the catalogue and the checked-in frame fixtures exist.

Out of scope, matching the design: a web relay, a second conversation or image store, more than one controller, phone changes to target, model, effort, approval mode, skills, or OAuth, editor integration, file drop, clipboard images, Review Compile, Review Build, Fix Selected Message, Indy, Synapse, lNet, and a cleartext fallback.

### 1.1 Traps the design already decided

These are notes, not extra work items. Do not reopen them.

- Codec is `AssistantMonitorCodec.pas`, not `AssistantProtocol.pas`. Provider JSON, OAuth tokens, API keys, and tool credentials never appear in a monitor message. `SignedIn` is a boolean. `Model` is the footer model id.
- v1 carrier is host-listens LAN: `ssockets.TInetServer` plus `opensslsockets.TOpenSSLSocketHandler`. Not `TWebSocketServer`. TLS is required. No cleartext retry.
- `MaxConnections` stays -1. That property is a lifetime accept count, not a simultaneous cap. `MaxSimultaneousConnections` is 2 so one spare socket can carry `rejected`.
- `OnConnect` only registers the socket and returns. After it returns, the accepted `THandleStream.Handle` is set non-blocking in `AssistantMonitorLan.pas`: Unix `fpfcntl` (`F_GETFL`, then `F_SETFL` with `O_NONBLOCK`), Windows `ioctlsocket` with `FIONBIO` and a `u_long` of 1. Do not call `SetSocketBlockingMode` or `TSocketServer.SetNonBlocking`.
- Each `OnIdle` performs at most one `SSL.Read` and at most one `SSL.Write` through the public `SSL` property. It does not call `TSocketStream.Read`, `TSocketStream.Write`, `TOpenSSLSocketHandler.Recv`, or `TOpenSSLSocketHandler.Send`. `IOTimeout` stays 0. `SSL_ERROR_WANT_READ` and `SSL_ERROR_WANT_WRITE` retry on the next idle and are not EOF. `SSL_ERROR_ZERO_RETURN` is a real close.
- The host fingerprint compare inside `pair` is not a second factor. The pairing code is the secret. The code is minted only when the user presses Pair, lives in memory, and is never written to `LazWorkflow.json` or `WorkflowLogger`.
- Remote tool approval defaults off. Codex `TAssistantToolBroker.OnApproval` stays nil. v1 remote approval is the native tool loop only.
- The bridge finds `TProjectAssistantForm` by scanning `Screen.CustomForms` for a form of that class that is not `csDestroying`, the same scan as `AssistantHostTurnOrPlanActive`. It does not call `CreateProjectAssistantForm` or `IDEWindowCreators.ShowForm`. A missing window is `error` / `no_session` with the message "The Project Assistant window is not open."
- Main-thread commands use `TThread.Queue`, a generation, and `Cancelled` / `Claimed`. The 5-second wait is only the non-pumping stall. A modal depth above zero returns `host_busy` immediately and does not call the form. That is not a 5-second wait.
- `getifaddrs` is not declared in this FPC tree. Interface enumeration stays in `AssistantMonitorForm.pas` as explicit externals. The LAN unit receives a bind address string and does not list interfaces.

### 1.2 Use LCL and FCL. Do not reimplement them

LCL owns the IDE surface. FCL owns JSON, hashes, sockets, and TLS. Application code owns the catalogue, the session rules, and the `LAM1` frame layout. That frame layout is not a second TCP stack. `fcl-web` `TWebSocketServer` was checked and rejected in the design: it would couple the catalogue to an HTTP upgrade. The carrier still uses FCL `TInetServer`. Do not add Indy, Synapse, lNet, a hand-rolled HMAC, a hand-rolled base64, a hand-rolled SHA-256, a PEM writer, or direct `sslRead` / `sslWrite` calls.

Name the facility in the unit that uses it:

- JSON: `fpjson` and `jsonparser`, the same units `WorkflowSettings` uses. No second parser.
- Random, hex, and base64url: `fphashutils.CryptoGetRandomBytes`, `BytesToHexStr`, and `BytesEncodeBase64`. `GrokOAuth.pas` already calls these. Do not copy those wrappers into the monitor package and do not write new ones.
- HMAC and certificate fingerprint: `fpsha256.TSHA256.HMAC` or `TSHA256.HMACHexa`, and `TSHA256.DigestBytes` for the DER fingerprint. Not a manual HMAC loop.
- Image parts: FCL unit `base64` (`EncodeStringBase64` / `DecodeStringBase64`), already used by `AssistantImageAdapters.pas`. Not `AssistantImages.EncodeBase64`, and not a new encoder.
- Frame length: `htonl` and `ntohl` from the `sockets` unit that `ssockets` already uses. Not a hand-rolled byte swap.
- Listen path: `ssockets.TInetServer`, `TSocketStream`, `TSocketHandler.CanRead`, and `TSocketHandler.Select`. TLS is `opensslsockets.TOpenSSLSocketHandler`. Reads and writes go through the public `SSL: TSSL` property (`Read`, `Write`, `Pending`, `GetError`, `Version`). OpenSSL load is `AssistantHttps.EnsureOpenSSLReady`. Certificates are `CreateCertGenerator` and protected `CreateSelfSignedCertificate`, stored as the DER bytes `UseCertificate` already parses. No `InitContext` copy and no `PEM_write_bio_X509`.
- Threads and waits: `TThread`, `TThread.Queue`, `SyncObjs.TRTLCriticalSection`, and `TRTLEvent`. Not a custom scheduler, and not `Synchronize` from the listen thread.
- Files and settings: `SafeFileAccess.ProtectOwnerOnlyFile`, `ReadWorkflowSection`, and `WriteWorkflowSection`.
- IDE surface: a streamed LCL form, `TActionList`, and `IDEIntf` menu registration (`RegisterIDEMenuCommand` on the existing Assistant menu). Desktop dialogs stay `MessageDlg` / `InputQuery` through `RunAssistantModal`. The phone path does not invent a second dialog stack.

Two platform calls were checked and are not in LCL or in this package's FCL units. Keep them as thin as the design already states. Do not grow them.

- Accepted-socket non-blocking. `TNonBlockingSocketStream.SetSocketBlockingMode` is the client `Connect` path and puts the socket back to blocking. `TSocketServer.SetNonBlocking` runs `fpfcntl` on the listen socket only, and that call is inside `{$ifdef Unix}`, so on Windows it sets a flag and leaves the accepted handle blocking. The two lines in `AssistantMonitorLan.pas` are those helpers' own calls (`fpfcntl` with `F_GETFL` / `F_SETFL`, or `ioctlsocket` with `FIONBIO`), applied to the accepted `THandleStream.Handle`. They are not a socket class.
- Interface list. LCL has no adapter enumeration. This FPC tree does not declare `getifaddrs`. `GetAdaptersAddresses` is in `winunits-jedi`, which this package does not require. The form unit declares those two externals and reads the IPv4 address. Do not shell out to `ip` or `ifconfig`, and do not add Indy to get `GetLocalAddressList`.

The Android client is not an LCL process. It uses `javax.net.ssl.SSLSocket` and `EncryptedSharedPreferences`, not a third-party HTTP client and not a hand-rolled TLS stack.

## 3. Codec, frames, and session core

The package compiles. It does not register a menu and it does not open a port. Catalogue version is the integer `1`. Implement the tables in the design's Message catalogue, Framing, and Session state machine sections. Do not invent types.

### 3.1 Package file and transport-neutral units
Status: complete

Add `Packages/LazAssistantMonitor.lpk` with the metadata in section 1. File entries for this item are `AssistantMonitorCodec.pas`, `AssistantMonitorFrames.pas`, `AssistantMonitorSession.pas`, `AssistantMonitorCarrier.pas`, and `AssistantMonitorSettings.pas`. No register unit yet.

`AssistantMonitorFrames.pas` owns `LAM1` framing:

```text
Offset 0   4 bytes  ASCII LAM1
Offset 4   uint8    version = 1
Offset 5   uint8    flags = 0
Offset 6   uint16   reserved = 0
Offset 8   uint32   payload length, big-endian
Offset 12  payload  UTF-8 JSON, length bytes
```

Allocate the payload buffer only after the length field passes the 262144-byte cap. A length above the cap closes the socket before the body is read. Reject a bad version, a short frame, and a non-UTF-8 payload. Encode and decode the length with `htonl` and `ntohl`. Parse the body with `fpjson`. Encode image parts with the FCL `base64` unit. The facilities are listed in section 1.2. Do not add a byte-swap helper, a JSON scanner, or a base64 alphabet.

`AssistantMonitorCodec.pas` maps every v1 type in the design, including both `hello` shapes and multi-part `image_data`. Every object has `v`, `id`, and `type`. `id` is at most 64 characters and uses the `TaskIdIsSafe` character set. Unknown `type` produces `error` / `unknown_type` and does not change session state. Wire names are snake case.

Lock these limits in the codec, not in a later UI:

- Listen port default 56122, one above `GrokOAuthRedirectPort`.
- User `send` / `steer` text 65536 characters, rejected with `payload_too_large`.
- Tool card body 4000 characters, the same cap as `MaxToolEventChars`, with `truncated: true` when the trace body was longer.
- Answer and thinking bodies split when one body exceeds 200000 bytes. Each part has `part`, `part_count`, and `revision`.
- One `image_data` part holds at most 190000 decoded bytes. Base64 of that size is 253336 characters. With about 8 KiB of envelope the frame stays under 262144 (253336 + 8192 = 261528).
- One `image_get` decoded budget is 1048576 bytes. Larger files are `image_unavailable` / `too_large`. The socket stays up. `missing` and `refused` are the other reasons named in the design. `AssistantImageMaxFileBytes` (8 MiB) is a store limit, not a frame limit.
- `snapshot.turns` is the newest 30 stored turns plus the live turn. Index rows only. `prompt_preview` is the store's existing `PromptPreview`.
- Mode strings are `AssistantModeToStr` values: `inspect`, `document`, `plan`, `build`, `chat`.

`AssistantMonitorCarrier.pas` is the seam from the design, including `SetFrameHandler`, `mcsConnecting`, and the interface GUID. No relay class is compiled. `TMonitorSession.AttachCarrier` stores the interface and sets the frame handler to the session's inbound method. The session owns the codec and the state machine. It does not use `TInetServer`.

`AssistantMonitorSettings.pas` is the only writer of the `monitor` section. Read with `ReadWorkflowSection('monitor')`. Write with `WriteWorkflowSection('monitor', Section, ErrorText)`. A missing section is the default object: `enabled` false, `port` 56122, `bind_address` empty, `bind_all` false, `remote_approval` false, `clients` empty. The checkbox defaults off, so `bind_all` wins only when it is stored true.

### 3.2 Session rules without a socket
Status: complete

Implement `TMonitorSession` against an in-memory carrier double that delivers frames through `SetFrameHandler`.

State names and edges are the design's state diagram. `Listening` to `Accepted` is the TLS handshake completing, not `hello`. A first connection sends `hello` with `client_name` and `client_version` only, then `pair`. A reconnect sends `hello` with `client_id`. The host replies `hello_ok` with a 16-byte nonce from `CryptoGetRandomBytes`, hex, single use, 30 seconds. `auth` is HMAC-SHA256 of that nonce, keyed by the stored session token, using `fpsha256`. Verifying `auth` enters `Live`. `pair_ok` is the frame sent after a successful pair check. It is not the transition.

Before `pair` succeeds or `auth` verifies, accept only `hello`, `pair`, `auth`, `ping`, and `bye`. Any other type is `rejected` / `auth` and the socket closes. `rejected.reason` is one of `protocol`, `pair_code`, `fingerprint`, `expired`, `auth`, `revoked`, `busy`, `disabled`.

The pairing code is 10 characters from the Crockford alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ`, drawn with rejection sampling from `CryptoGetRandomBytes`. It is absent until the test, or later the Pair button, asks for one. Discard it 120 seconds after that request, after one success, or after three failures. Three failures close the socket. A discarded code stays discarded. The listener does not mint or rotate a code. On success allocate `client_id` (16 random bytes, hex via `BytesToHexStr`) and `session_token` (32 random bytes, `BytesEncodeBase64` with the same URL-safe arguments `GrokOAuth.BytesToBase64Url` already uses). Append a client record, save the monitor section, move to `Live`, then send `pair_ok` once. Reconnect HMAC is `TSHA256.HMAC` of the nonce, keyed by that token. Do not write an HMAC.

`bye` / `revoked` is only for a socket that was already `Live` or `Busy`. A new socket whose `client_id` is already revoked gets `rejected` / `revoked` and never enters `Live`. Disabling the listener sends `bye` / `disabled` and keeps the client records. Revoke deletes that record, saves, and closes a live socket.

`Busy` mirrors `FSending` or `FPlanAgentRunning` once the bridge exists. In this item the session records the flags the command sink reports. The phone may `steer` and `stop` in `Busy` only when `can_steer` or `can_stop` is true. `send`, `set_mode`, `new_conversation`, `run_plan`, `work_on_plan`, and `run_task` fail with `host_busy` while the matching desktop control is disabled. `remove_plan` and `insert_task` fail with `host_busy` while sending or the plan agent is running. `select_plan` and `new_plan` follow `SetSending`.

Backpressure: outbound queue of 32 frames, then coalesce. Coalesce window 100 ms. At most one unsent `transcript` frame per live turn. A newer observation replaces that frame's blocks and bumps `revision`. Heartbeat is ping after 15 seconds of silence. Dead session is 45 seconds with no frame. Partial frame is 10 seconds from the first byte of an incomplete header or body.

Approval rules the session test must lock, even before the IDE waiter exists: an approval decision is ignored when remote approval is disabled and when the tool id is already closed. One display-only Ask publishes a single `approval_requested` with `decisions_accepted` false and closes with `desktop`. A bare signal while the stored decision is `aadNone` is not an allow. Cancel stores `aadStopped` during a pending approval and does not record a tool execution.

Logging, when a logger is available, uses area `AssistantMonitor` and includes lengths, reason codes, bind address, and port. It omits the pairing code, session token, HMAC, prompt bodies, tool arguments, and image bytes.

### 4.1 One stable DER certificate

`TMonitorTlsHandler` descends from `TOpenSSLSocketHandler` and calls protected `CreateSelfSignedCertificate`. Before the one-time mint set `CertGenerator.CommonName` to `LazAssistantMonitor`, `ValidFrom` to `Date - 1`, and `ValidTo` to `EncodeDate(2049, 12, 31)`. The socket test asserts the same fingerprint on two sequential connections. Do not hash the PEM text, and do not call OpenSSL `SHA256` directly when `fpsha256` already does this.

### 4.2 Listen thread
Status: not started

Add `Source/LazAssistantMonitor/AssistantMonitorLan.pas` and its lpk file entry. `TMonitorListenThread` is a `TThread` descendant. `FreeOnTerminate` is false. The owner in `AssistantMonitorMain` will call `WaitFor` on shutdown. The constructor copies bind address, port, and certificate paths, then calls `Inherited Create(False)` last.

Follow `TGrokOAuthCallbackThread.Execute` for the listen shape: `TInetServer.Create(BindAddress, Port)`, `AcceptIdleTimeOut` 250, `OnConnect`, `OnIdle`, `ReuseAddress`, `OnCreateClientSocketHandler`, `Bind`, `Listen`, `StartAccepting`. `MaxConnections` stays -1. `MaxSimultaneousConnections` is 2. `Bind` and `Listen` failures are stored as an error string and queued to the main thread. The listener stays stopped. The carrier does not pick another port.

Apply the non-blocking and single-read rules in section 1.1. The two non-blocking lines are the FCL helpers' own calls, applied to the accepted handle because those helpers do not cover it. See section 1.2. Do not add a socket class around them. A read is due when `SSL.Pending > 0`, when `CanRead(0)` is true, or when a previous `WANT_READ` is still owed. `Pending` does not replace the TCP poll. A positive read count is appended to that socket's frame buffer. A short write keeps the unsent tail. The spare `rejected` / `busy` frame is itself one `SSL.Write` from `OnIdle`. Stay on `TSSL`. Do not call `sslRead` or `sslWrite`.

The partial-frame limit is the timestamp of the first byte, checked on each idle after those calls return. It is not a read that blocks for 10 seconds.

`OnConnect` does not pair. Pairing and steady-state frames are parsed from bytes already appended to a per-socket buffer. Bytes for the IDE cross through a locked outbound queue and a locked inbound command queue. `OnIdle` drains at most one queued outbound buffer per socket per idle.

With the simultaneous cap at 2, `StartAccepting` still calls `OnConnect` for the second socket. A further connection is closed inside `StartAccepting` and reported with `DoConnectionDropped` before `OnConnect`. Closing the spare socket after the reject frame does not call `StopAccepting`. When the controller drops, the thread stays inside `StartAccepting` and accepts again.

The socket test binds `127.0.0.1` with port 0. `TInetServer.Port` stays 0 after `Bind`. Read the kernel port with `fpGetSockName` on public `TInetServer.FPSocket`. Do not read `TInetServer.Port`.

`TMonitorLanCarrier` implements `IMonitorCarrier`. `Start` binds and reports `mcsListening`, then `mcsConnected` for the controller socket. It never reports `mcsConnecting`. v1 does not compile a relay.

## 6. IDE bridge, menu, and options form

This is the first slice that connects a socket to a live assistant session. Remote approval still defaults off.

### 6.1 Bridge and remote approval waiter
Status: not started

Add `AssistantMonitorBridge.pas` and `AssistantMonitorApproval.pas`, plus their lpk entries.

The bridge registers `SetAssistantSessionListener` on the main thread from `RegisterAssistantMonitor`. It does not replace the form's trace handler. Snapshot and command calls stay on the main thread after the form lookup in section 1.1.

Each queued command carries a generation, `Cancelled`, and `Claimed` under a lock. The queued method sets the completion event in `Finally`. It calls the form only when, under the lock, `Cancelled` is still clear and `AssistantModalDepth` is zero, and it then sets `Claimed`. On the 5-second timeout the LAN thread sets `Cancelled` when `Claimed` is still false, then sends `error` / `host_busy`. When `Claimed` is already true it does not also send `host_busy`. A command whose `Cancelled` flag is set by the time the queue runs does not call the form. A depth above zero returns `host_busy` immediately. The display-only `approval_requested` is a separate queued observer notify, posted before the dialog. A depth above zero does not drop it.

Coalesce transcript frames as specified in section 3.2. The bridge keeps at most one unsent `transcript` frame per live turn. Tool bodies on the wire are capped at 4000 characters. The listener only enqueues. It does not build provider JSON.

`AssistantMonitorApproval.pas` is the waiter registered with `SetAssistantRemoteApproval`. It returns `Handled` false immediately when `remote_approval` is false, when the approval mode is not Ask, or when `RunningOnMainThread` is true. It does not arm an event or publish in those cases. Otherwise it creates a `TRTLEvent`, calls `ArmAssistantApprovalWait`, and calls `PublishAssistantApproval` with `DecisionsAccepted` true. The waiter does not send a frame. Only the bridge writes `approval_requested`, copying `DecisionsAccepted` from the notice. It does not re-read `remote_approval` to invent that flag.

The wait slices `RTLEventWaitFor` at about 200 ms, then reads the stored decision and the abort callback. `aadAllow` allows. `aadDeny` denies. `aadStopped`, or an abort callback that reports `Terminated`, `FTerminalNoted`, or `ServiceWasDetached`, denies with `approval_closed` reason `stopped`, including when the stored value is `aadAllow`. `aadNone` keeps waiting. Timeout is 120 seconds and denies with reason `timeout`. Workers do not call `CheckSynchronize`. The waiter calls `ClearAssistantApproval` on the armed path. Only the bridge writes `approval_closed`.

Phone Allow and Deny, and the monitor form's Allow and Deny, store `aadAllow` or `aadDeny` and then signal. They do not call `ExecuteAssistantToolForMode`. A second answer, or an answer after Stop, receives `approval_closed` / `finished` or `stopped` and does not start the tool. `Summary` is `Copy(Trim(ArgumentsJson), 1, 240)` plus an ellipsis when longer.

Changing `remote_approval` applies to the next tool prompt. The listen thread reads a settings snapshot taken on the main thread at start. A save during a session does not race the socket configuration. Changing port or bind address applies on the next listener start. Revoke saves immediately and signals the live session.

Listener and queued methods catch exceptions and call `ReportPluginException` so a monitor fault cannot escape `CheckSynchronize` into the Qt loop. In-process counters on `TMonitorSession`, shown later on the form: listener state, bound address, port, last error, connected client name, seconds since the last frame, frames sent, frames dropped by coalesce, and whether remote approval is on. The monitor does not write `StatusFooter` labels.

### 9.1 TLS session and encrypted store
Status: not started

`LanSession` uses `javax.net.ssl.SSLSocket`, not a third-party HTTP client. Reads and writes run on `Dispatchers.IO`. A custom `X509TrustManager` accepts the connection only when the SHA-256 of the server certificate equals the pinned fingerprint. A failed handshake does not retry in cleartext. A pin failure does not delete the host's client record.

`HostStore` uses `EncryptedSharedPreferences` for host address, port, fingerprint, `client_id`, and `session_token`. It holds no model provider secret. Clearing the store forgets the pairing on the phone. The host record remains until the desktop revokes it.

Reconnect backoff is 1, 2, 4, 8, then 30 seconds, then `auth` and `refresh`. Disabling the listener pauses backoff while connects are refused. The unsent prompt draft is kept across disconnect.

### 9.2 Compose screens
Status: not started

`app` depends on `protocol`. Compose Material 3. `MonitorViewModel` reduces messages into one `UiState` as the design specifies: `snapshot` replaces view, plan, tasks, and the turn index; `transcript` replaces the live turn when `revision` is newer; `turn_data` fills a selected history turn; status, mode, target, plan, and tasks patch those parts; `approval_requested` opens the sheet; `approval_closed` closes it; `insert_result` fills the prompt; `rejected` and socket EOF set the disconnected banner and keep the draft.

Screens, and only these remote actions:

- Pair: host address, port default 56122, fingerprint, one-time code, connect. Protocol mismatch, bad code, and TLS pin failure stay on this screen.
- Conversation: connection, target caption, model, and phase. Blocks in order: user, thinking, tool card, steer, subagent, note, answer. Image blocks request `image_get` once, reassemble parts, and cache the bitmap. `image_unavailable` names the reason and leaves the session up. The action button caption is Steer only when `can_steer` is true and Send only when `can_send` is true. It is not taken from `view.busy`. Stop is enabled when `can_stop` is true. Mode is a segmented control of the five mode strings, disabled when `can_change_mode` is false. No image attach.
- Plan: title, path, rows, Work on this, Run, Stop, New, Remove. No Open action. No Done button.
- Tasks: Run and Insert only for rows the snapshot marks runnable. Format and compile-first rows are visible and disabled, with the desktop-only reason. A note field appears when `needs_note` is true.
- Approval sheet: tool name and the 240-character summary. When `decisions_accepted` is false the buttons are absent. When true, Allow and Deny send `approval_decision`. A Codex or Claude turn does not raise this sheet.

`./gradlew :app:assembleDebug` is the compile check. Two LAN setups are documented in the design: the host's private IPv4, or an emulator with `adb reverse tcp:56122 tcp:56122` and the IDE bound to `127.0.0.1`.
