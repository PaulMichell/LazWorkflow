# Image support in the Project Assistant

Generated by Lazarus Project Assistant.

The assistant can only submit text. Paste on the prompt is `PasteFromClipboard`, which requires `CF_TEXT`. Send does nothing when the memo is empty. User turns, `MessagesJson`, and both native request builders store `content` as one string. Codex `turn/start` sends a single `{type:text}` item. The transcript is styled Markdown and does not draw images. A pasted or chosen picture never reaches the model, and it would not survive a reload if it did.

Full support means a picture the user loads, pastes, or drops is kept with the conversation, shown at a readable size, and sent to the model on later turns until compaction drops it. The same picture can be opened, copied, and saved. Inspect, Plan, and Build can all attach images. Images are user input, not a write, and they do not widen mode permissions.

Bytes never go into `conversation.jsonl`, trace JSON, the system prompt, logs, or the token character count. The store holds files. The transcript and the model payload hold references.

### Out of scope
Image generation, image edit, and the imagine endpoints stay out of the model picker. Do not fetch `http`, `https`, or `file` URLs from Markdown or from model text. Do not play animated GIFs. Do not add an IDE screenshot tool. Do not teach `StyledMarkdown` to load arbitrary images. Do not send image bytes to subagents or to `CompleteOnce`.

## 1. Store

Pictures are copied into the project `.assistant` store at attach time. The original path is not kept. A later delete or edit of the source file must not blank the transcript.

### 1.1 Add an image unit and a store directory
Status: complete

Add `Source/LazAssistantTools/AssistantImages.pas` and register it in `Packages/LazAssistantTools.lpk`. Keep decode, limits, and path checks in that unit. Do not add them to `ProjectAssistantForm.pas`, `AssistantService.pas`, or `GitDiffView.pas`.

Accept PNG, JPEG, GIF, BMP, and the other still-image extensions `FileExtensionIsImage` already names, by stream sniff rather than by extension alone. Use FPImage readers that a test can register. Take the first GIF frame and record that animation was discarded. Skip WebP unless a reader is already linked. Reject anything that is not a readable still image.

Before reading, refuse a file over 8 MiB. Before decoding, refuse a side over 16384 or a pixel count over 16 million. Those are the same ceilings as `TryShowImageFromStream`. Reject symlinks when reading a stored file back. Copy the accepted bytes into `.assistant/images/` under the same root `AssistantProjectPaths` uses for `conversation.jsonl`. The stored name is an id, not the user's path.

Write two files per image: the display image, and a model upload derivative whose long side is at most 2048 and whose encoded payload is at most 4 MiB. Prefer PNG. Use JPEG when PNG would miss the cap. Record id, original name, mime, width, height, and both relative paths. Return a clear error string for oversize, undecodable, and unsupported input. Do not log pixel bytes or data URIs.

### 1.2 Persist references on the turn and on the user message
Status: complete

Extend `TConversationTurn` with an attachments JSON array. `BuildTurnJson` and `ParseTurnLine` round-trip it. Old lines have no field and load as no images. `prompt` stays the user's words. An image-only turn keeps an empty prompt and a history preview of the file name, or `Image` when there is no name.

`TAssistantMessage` gains an image-ref list, only meaningful for `amrUser`. `ExportUnstoredMessagesJson` and `RestoreMessagesJson` carry the refs as sibling fields, not inside `content`. `RebuildClientFromConversation` must restore those refs. A reload that restores only `Turn.Prompt` will forget the picture on the next request.

`TTraceBlock` for `tbkUser` stores the same ids. Trace JSON stays free of bytes. Export Markdown names the files. It does not embed them.

### 1.3 Archive and delete the files with the conversation
Status: complete

Archiving the current conversation copies or moves the referenced image files with that archive so Activate still shows them. Deleting a conversation deletes image files that no remaining current or archived turn references. Starting a new chat does not delete the archived copies. A missing file paints as an unavailable tile with the name and size. It does not drop the turn.

## 2. Model payload

The live native path is `TAssistantActor.BuildRoundJson`, which calls `ExportSamplerItems` and then `BuildResponsesRequestJson` or `BuildChatCompletionsRequestJson`. `TAssistantService.BuildRequestJson` must not become a second, text-only path for the same turn. Text-only messages keep today's string `content`. A user message with images becomes a content array on that message only.

### 2.1 Attach refs when the turn is submitted
Status: complete

`SubmitUserTextEx` calls `AddUserMessage` with the model text and image refs. The visible prompt stays the user's words. Empty words become the look sentence only in the model text. IDE context stays a text suffix. Parent system prompts include the image sentence. An explicit input-modality list without images disables attach and says why; a missing list allows attach. A model image rejection leaves the composer refs. `StartCodexReply` calls `AddUserMessage` for a text turn and refuses images, because this client's `turn/start` input is text only. The strip that fills those refs is still 3.1. This package was not type-checked: the IDE compile target was not LazAssistantTools.

`AddMessage` stays text-only for tools, steer notes, and subagent prompts. Add a user-message entry point that takes text plus image refs. `SubmitUserTextEx` and `StartCodexReply` call it. IDE context remains a text suffix. It is not stuffed into an image part.

When the user sent no words, the visible prompt stays empty and the model text part is `Look at the attached image(s).` Some wires reject an image part with no text part. Do not show that sentence as the user's words.

Cap a submission at 8 images. The constant lives in `AssistantImages`.

Add one system-prompt sentence: user messages may include images; describe only what is visible; do not invent image contents; do not fetch URLs. Do not infer vision support from the model name. If `/language-models` has an explicit input-modality list and images are absent, disable attach for that model and say why. If the list is missing, allow attach. If the request then fails because the model rejected an image, show that error and leave the pictures in the composer.

### 2.2 Emit image parts on both native wires
Status: complete

Confirm the part shape against the xAI image-understanding guide and one saved fixture before freezing the serializer. The working shape, used only after that check:

- Responses: user `content` is an array of `input_image` (`image_url` as a `data:` URI of the upload derivative) followed by `input_text`.
- Chat Completions: user `content` is an array of `image_url` objects (`url` data URI, `detail` omitted or `auto`) followed by a `text` part.

`TSamplerInputItem` needs an image-ref list so `ItemToResponsesJson` and `ItemToChatCompletionsJson` can emit the array. String content remains the case with no images. System, assistant, tool, reasoning, and provider-output items do not grow image parts. A fixture test asserts a text-only request is unchanged and an image request contains the data URI once, not also inside a duplicated string `content`.

### 2.3 Count images in the budget and drop them on compact
Status: complete

`MessagePayloadChars` must not count file bytes or base64. Add a flat 1100 tokens per image that is still on the next request, and show the image count in the context breakdown. Compact and the 95% auto-new-chat guard must see that number.

When trimming old history, remove image parts from messages outside the recent window and append `[Image omitted from model context: name, WxH]` to that message's text. Keep the display files. Do not resend a dropped image on the next native request.

### 2.4 Send images on Codex, or say the runtime cannot
Status: complete

Read the app-server `UserInput` schema at the protocol version this client already speaks (`threadId`, `turn/start`, camelCase). The reference is https://learn.chatgpt.com/docs/app-server. Do not mix in a guessed `local_image` field.

The managed runtime is started with minimal filesystem read and network off, so a path outside its readable root will fail. Prefer an in-band image item over a local path. If that item does not exist in this protocol version, leave Codex attach disabled and set the action hint to the reason. Do not pretend a text note is the picture.

When the item exists, `StartTurn` sends the current submission's images plus text. Older Codex recap stays text. Name omitted images in the recap. Do not paste every historical data URI into the ephemeral thread. `AssistantCodexClientTest` covers the request body with a fixture and no live process.

Decision: image support stays on the Grok connection. This client sends a text item only, and Attach says why.

## 3. Composer

The prompt is `InputMemo` in `InputPanel`. Send is `SendAction`. Paste is `InputPasteClick`. Static chrome goes in `ProjectAssistantForm.lfm` through the action list. Thumbnail buttons are dynamic: create them with owner `Nil`, parent them to the streamed strip, and free them in code. Do not `Create(Self)` runtime thumbnails. The designer must not write them back into the form.

### 3.1 Attach, paste, and drop
Status: complete

Add `AttachImageAction` to the form action list, the Session menu, and a button on a streamed strip in `InputPanel`. On-screen order is Attach, then thumbnails left to right. The strip is hidden when empty so the resting memo layout does not grow. Each thumbnail shows the image scaled down, the file name, and a way to remove that one image. Removing does not delete a file that a sent turn already references. It deletes an unsent store file.

The file dialog starts at the project root. The filter lists the accepted extensions. A rejected file produces a short dialog and adds nothing.

Ctrl+V and the Paste menu must run before `TSpellMemo.PasteFromClipboard`. Probe `image/png`, `image/jpeg`, `image/bmp`, and `CF_PICTURE`, then normalize through `AssistantImages`. GTK is the first platform; use LCL clipboard APIs so Windows and Cocoa take the same path. If the clipboard has an image and text, attach the image and still paste the text. If it has only an image, attach it and do not insert a character. If it has only text, paste text as today. A failed image probe must not swallow a text paste.

Enable drop files on the input panel. Accept the same images. Ignore other dropped files. Do not turn a dropped `.pas` into an attachment.

### 3.2 Send with images and no text
Status: complete

`SendActionExecute` returns immediately when the trimmed memo is empty. Allow send when the memo has text or the strip has an image. Clear the memo and the strip only at the same point send already clears the memo, after the sign-in check. A refused send leaves both intact.

While a turn is running, Send is a steer. Until steer accepts images, do not clear the strip and do not drop the pictures into the steer note. Steer the text if there is any, and tell the user the pictures stay in the composer for the next message.

## 4. Transcript

`StyledMarkdown` keeps image syntax as literal text. Leave that rule in place. Attachments are painted by the conversation surface, not by the Markdown parser.

### 4.1 Draw the pictures in the user block
Status: complete

A missing file draws a named tile and increases the section height. A file that is present is not painted.

On reload, rebuild the user block from the turn prompt plus attachment ids. Draw the pictures above the user's words, inside the user bubble, scaled to the bubble width and not enlarged past 1:1. Follow the surface DPI the layout already receives.

The image row is part of the section height in `AssistantConversationLayout`, not an overlay. Scroll, keyboard navigation, and hit-testing must land on the text below the pictures, or on the picture when the pointer is in the row. A missing file is a named unavailable tile of fixed height. `AssistantConversationSurfaceTest` can assert height from a known image size without a live clipboard.

### 4.2 Open, copy, and save
Status: complete

Double-click or Enter on an attachment opens a small streamed dialog, `AssistantImageView`, with a scrollable 1:1 paint box and Esc to close. Do not shell out to an external viewer.

The conversation context menu gains Copy Image and Save Image when the pointer is on an attachment. Copy places a PNG on the clipboard. Save uses a save dialog defaulting to the original name. Ctrl+C on a text selection still copies text. Copy Last Answer stays text.

## 5. Other ways a picture should travel

These are part of full support. They use the same store and the same wire parts. They do not invent a second image pipeline.

### 5.1 Read a project image into the next model turn
Status: not started

Add a read-only tool, available in Inspect, Plan, and Build, that takes a project-relative path. Resolve it with the existing project sandbox. Refuse paths outside the root, symlinks that escape, and files that fail the `AssistantImages` limits. Copy the accepted image into the store and attach the refs to that tool result's following user-visible model input, using the same content-array rules as a composer attachment. The tool result text is the name, dimensions, and id only.

Do not weaken `IsBlockedBinaryExtension` for `write_file` or `replace_in_file`. A PNG is still not a text edit.

### 5.2 Steer an image into the running turn
Status: not started

`EnqueueSteer` and Codex `turn/steer` are text today. Extend both so a steer can carry the same image refs as a user message. The native steer is injected at the next model gap as a user message with image parts, not as a string that describes the file. Codex sends the protocol image item on `turn/steer` when 2.4 found one, and otherwise keeps the composer warning from 3.2.

A steer still cannot widen mode permissions. It cannot add images to a subagent.

### 5.3 Keep an image the model returns
Status: not started

The sampler currently keeps text deltas only. On a completed native response, if an output content part is an image or a `data:` image, run it through the same size and decode limits, store it, and show it on the answer block. A response with no such part is unchanged. Do not call an image-generation endpoint to create that part. Add a fixture to `AssistantSamplerTest` so a text completion still parses and an image part is saved once.

If the completed fixture has no image part type, record the observed schema in the test comment and skip the branch. Do not guess a field and send it.
