# Keep the Plan tab enabled in every mode

Generated by Lazarus Project Assistant.

The sidebar Plan tab is disabled in Chat, Inspect and Document modes. That rule is left over from older versions. The controls on the sheet already decide for themselves whether they can act: `UpdateWorkActions` enables Open, Close, New, Run Plan, the active-plan combo and Browse from the active plan, `FSending` and `FPlanAgentRunning` only, and `RunPlanIsAvailable` already says it is not limited to Plan or Build because Run Plan switches to Build itself. Nothing on the sheet needs the mode gate.

The gate lives in three places in `Source/LazAssistantTools/ProjectAssistantForm.pas`:

- `UpdateModeSidePanels` (called from `SyncModeUi`) sets `PlanSheet.Enabled` from `ActiveMode In [amPlan, amBuild]`, and moves the sidebar to History when the Plan sheet is showing and the mode does not allow it.
- `SidebarPagesChanging` refuses a move onto the disabled Plan sheet.
- `SidebarPagesChange` bounces a disabled Plan sheet back to History, guarded by the field `FAdjustingSidebarPage`.

`ProjectAssistantForm.lfm` does not stream `Enabled` on `PlanSheet`, and only `SidebarPages` names the two handlers (`OnChange`, `OnChanging`).

## 1. Remove the mode gate on the Plan sheet

### 1.1 Drop the mode rule and its page guards
Status: complete

In `ProjectAssistantForm.pas`:

- In `ProjectAssistantForm.lfm`, remove `OnChange = SidebarPagesChange` and `OnChanging = SidebarPagesChanging` from `SidebarPages`, so the streamed tree and the class stay in step.

Do not set `PlanSheet.Enabled` anywhere. Do not change `UpdateWorkActions`, `RunPlanIsAvailable`, or any plan action's enable rules, captions or hints. Do not select the Plan sheet when the mode changes: the page the user chose stays where it is.
