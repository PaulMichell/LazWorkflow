# Granular monitor sync

Generated by Lazarus Project Assistant. Revised 2026-11-03 after a code review of the live path (transport queues, pump cadence, slice numbering, resume reconciliation).

Change the remote-monitor synchronising process so a connected phone reacts quickly, and so the last committed conversation can be read with no link. Two means, in this order: a link thread that writes as soon as a frame is ready, and a smaller grain of transfer that replaces the frame types already in flight rather than adding to them.

This plan supersedes the sync portion of `Documents/Plan-20261029-035918.md`. That plan's libraries exist (mirror log, `TMonitorOutbox`, Room store, `SyncApplier`). The live wire does not use them, and its transport items 4.1 to 4.3 were never built. This plan absorbs those transport items. Do not reopen the others, and do not implement catalogue 3 beside catalogue 2. A build that still applies both `patch` and `event` to the screen is a failed cut, not a checkpoint.

Out of scope: pairing, TLS, HMAC, dictation, the image pixel pipeline, and a redesign of command idempotency. Command acknowledgements, pongs, and approvals must not wait behind content. They are not otherwise changed.

## 1. What the link does today

The phone and the IDE still speak catalogue 2 (`MonitorCatalogueVersion = 2` in `AssistantMonitorCodec.pas`). Catalogue 3 is specified in `Documents/MonitorProtocolV3.md` and is not the live wire. The October 2026 plan marked the event log, the Room store, and the sync applier complete. Those pieces were then left beside the old path. That is the drift.

Content moves as documents, not as slices.

- `PumpMirror` runs from a 150 ms `TTimer` on the IDE thread (`AssistantMonitorBridge.pas`). It copies the whole live turn from the form, calls `ObserveTurn`, then builds a `patch` from dirty blocks. A pure suffix can be an append. The first patch, and any edit that is not a suffix, sends the whole block body. Busy, phase, status text, and a ticking `ElapsedMs` ride in that same patch, so a flag change is a content step. The pump is also the only producer of mirror events, so an IDE change waits up to 150 ms before anything is queued.
- Resume is answered twice. `TMonitorSession.ServeResumeFromMirror` runs on the connection thread. `TAssistantMonitorBridge.AnswerResume` runs on the IDE thread. A matching epoch becomes one `catchup` blob of every stored patch. Otherwise the host sends snapshot pages of the open turn. A turn that does not fit 32 KiB is split into one page per block, and each page still carries the whole block body.
- `TMonitorMirror.ObserveTurn` records `turn_open`, `block_open`, `block_append`, `block_replace`, `block_close`, and `turn_close`. A `block_append` carries the whole suffix since the last pump, unbounded, and a `block_replace` carries the whole body. An event larger than the 8 MiB log budget is dropped by `AppendLocked`. Resume does not replay those events. It replays patches. The phone's `SyncApplier` only receives a decoded `event` (`LanSession.kt` offers it when `type` is `event`). The host does not send that type on the live path, so the applier does not see the stream the user is watching.
- The screen is `MonitorCoordinator` memory: patches, catchups, and snapshot pages. Room is a later full-document rewrite. `persistBoard` in `MonitorViewModel.kt` calls `saveScreen`, which keeps the previous `seq` and `streamId`. `watchRepository` paints those rows back onto the coordinator. Two writers, and the cursor does not describe the text. The phone's `ack` is paced by the coordinator from the patch cursor, not by the applier after a commit.
- There are three outbound queues in series, and only the first two know about priority. `TMonitorOutbox` is created by the session but used only to admit bulk items, which are then copied straight into the session's `FBulkSends`. The session lanes (`FControlSends`, `FLiveFrames`, `FPlanFrames`, `FBulkSends`, bulk capped by `MonitorOutboundQueueLimit = 32`) are drained by `DrainSends` into the carrier. The carrier (`TMonitorLanCarrier.Send`) holds one plain FIFO capped at `MonitorOutboundCap = 32`. Once a frame is in that FIFO, a pong queued later waits behind every frame ahead of it. That FIFO, not the session lanes, is why the pong arrives after 32 bulk frames.
- The socket is serviced from `TInetServer.OnIdle`. `RunIdleLoop` calls `select` on the listening socket only, with `AcceptIdleTimeOut = MonitorAcceptIdleMs = 250`. The accepted socket is not in that `select`, so neither a frame queued for the phone nor a ping arriving from the phone wakes the thread. One pass reads once and writes at most one frame (`WriteOnce`). Nothing outside the thread can shorten the wait. A plan that does not fit is replaced with the sentence "The plan is too large to cache on the phone."
- The last measured host harness (`Documents/MonitorLinkBaseline.md`, 2026-10-29) was 4 frames/s, a first frame at 251 ms, and a pong at 8261 ms behind 32 bulk frames. Re-measure before quoting those numbers again. The transport is the structural ceiling. Smaller payloads alone cannot meet a 150 ms response while the socket leaves once per quarter second, and neither can a 150 ms producer timer.

The two features fail for those reasons. Connected response waits on the pump timer, the idle poll, a FIFO with no priority, whole blocks, and history pages. Offline reading depends on a debounced copy of the in-memory screen, not on the frames that arrived. A gap can leave the last flags on screen while later content is discarded. An empty page can be filed as the conversation.

## 2. The sync this plan installs

One grain. One cursor. One store. One resume answer. One outbound queue, pulled by one link thread. No second decode path.

The cursor is the mirror head. The epoch string already stored by the host, and already kept by the phone as `hostEpoch` / `streamId`, is the stream id. Do not mint a second id. `conversation_id` is never `current`. The Room host key stays the installation host id the phone already stores, falling back to the pinned fingerprint only when that id is absent, so existing rows stay readable. Turn and block ids are stable across stream ids; that is what lets the phone keep its cache across a gap.

Three kinds of transfer:

- **State.** Latest value of one key. No sequence. Sent on change and before any content on resume. Keys required for a fast connected response: `status` (busy, sending, phase, status text, can-send, can-steer, can-stop, and `started_at` rather than a ticking `elapsed_ms`; the phone computes elapsed time) and `approval`. Other menus may follow. They must not block status.
- **Slice.** One mirror event, one sequence number. `turn_open`, `block_open`, `block_append`, `block_replace`, `block_close`, `turn_close`, `title_changed`. The mirror splits a long append into slices of at most 4 KiB of UTF-8, on a code-point boundary, when it appends them to the log, so every slice gets its own sequence number and its own offset. Splitting after the sequence is assigned would give several frames one sequence, which the apply rule below treats as duplicates. The phone applies a slice only when its sequence is the stored sequence plus one. A lower sequence is a duplicate. A higher sequence is a gap.
- **Fetch.** The phone asks for what it does not have: a block body from a byte offset, a turn that is not in the cache, an image, or the plan body. The host answers in pieces of at most `MonitorBlockDataBytes` (24 KiB). Each answer states the total byte length it describes, so later slices can be matched to it. Fetches are not pushed on connect.

Connected behaviour:

- The phone paints the Room conversation as soon as it opens, then sends `resume` with conversation id, stream id, and sequence. It does not wait for a snapshot to show cached text.
- The connection thread answers from the mirror. The IDE thread is not on the resume path. There is one answer.
- If the stream id matches and the log still holds every event after the sequence, the host replays those slices and nothing else. No catchup blob. No turn page.
- Otherwise the host sends state, then one outline: turn ids, indexes, prompt previews, and per block its id, kind, state, byte length, and a body hash. The phone reconciles in one transaction: it keeps every cached block whose hash matches, marks the others stale, removes turns and blocks the outline does not name, and stores the new stream id and head. Stale blocks are fetched when shown; the open block is fetched at once. Byte length alone is not identity; an edit can keep the length. An empty observation is not a conversation and must not be filed as one.
- Slices leave the host as the mirror produces them. The mirror log is the only retained copy; the link thread reads it by sequence. The host sends at most the credit window (512 KiB, matching the phone's `InboundCreditBytes`) beyond the last acknowledged sequence, so a slow phone slows the host instead of overflowing either side. A socket drop loses nothing that the log still holds.

Offline behaviour:

- Room is the only conversation the UI reads, connected or not. Disconnect does not clear it. Commands that need the host are disabled. Reading is not.
- Each applied batch commits the rows and the sequence in one transaction, and only then is the sequence acknowledged. A process kill must not show text the cursor does not cover.
- The plan's row summaries are state. The plan body is a fetch, stored when it arrives. Never replace a body with an error sentence in order to fit a frame.

Transport, required for the connected budget:

- A link thread owns the accepted socket. It waits on the socket and on a wake handle together, so a queued frame and an arriving ping both wake it at once. The accept loop only accepts and hands the socket over.
- Each wake reads everything readable and writes until the socket would block, taking control, then state, then slices within the credit window, then fetches.
- One queue: `TMonitorOutbox`. The session lanes and the carrier FIFO are deleted. No 32-frame cap applies to anything but bulk admission.

Budgets, from the existing plan, still the acceptance bar:

- IDE change to the phone screen while a turn streams: p95 under 150 ms on a LAN. This budget includes the producer: an IDE change must reach the mirror within 50 ms.
- Pong while slices or fetches are queued: under 100 ms.
- After a drop, the cached screen is visible immediately and the open-block gap is filled within 1 s, without re-sending cached history.
- With no network, the last committed conversation is readable, including stored bodies.

Do not grow `AssistantMonitorSession.pas`, `AssistantMonitorBridge.pas`, `AssistantMonitorCodec.pas`, `AssistantMonitorLan.pas`, `MonitorCoordinator.kt`, or `MonitorViewModel.kt` with the new path. Put host sync decisions in a new `AssistantMonitorSync.pas` and the link thread in a new `AssistantMonitorLink.pas`. Put phone apply rules in the existing `SyncApplier` path or a new file next to it. Deleting the hybrid should shrink the old files.

## 4. Transport first

This section changes no content format, so it ships before the cut and is measured on its own. It is the largest single gain for the connected response and the precondition for every budget.

### 4.1 One link thread with a wake handle
Status: not started

Add `Source/LazAssistantMonitor/AssistantMonitorLink.pas`, registered in the monitor package. The listen thread keeps `TInetServer` for accept, TLS accept, and the simultaneous cap, then hands the controller socket to a link thread and stops touching it. The `SSL` object is used by the link thread only.

The link thread loops on `fpPoll` over the socket and the read end of an `fpPipe` (Unix), or `select` on the socket plus a loopback socket pair as the waker (Windows), as the October plan's item 4.1 specified. It asks for write readiness only while a frame is ready or a write is owed. Each wake reads until `SSL_ERROR_WANT_READ` and hands complete frames to the session handler, then writes until the outbox is empty, the credit window is full, or `SSL_ERROR_WANT_WRITE`. Keep the owed-read-before-write rule from `WriteOnce`. Heartbeat and partial-frame timeouts use the poll timeout, not the accept timeout.

`TMonitorOutbox.OnWake` writes one byte to the wake handle. `AcceptIdleTimeOut` may stay 250 ms; it is no longer on any send or receive path.

Nothing is dropped silently. A bulk item the outbox refuses is answered `not_found` or left for the phone to ask again; it is never counted in `FFramesDropped` after the phone was told it was sent. A control or state frame that cannot be queued closes the link with `bye`.

## 5. Host sends slices

### 5.1 Mirror events are the only content the new unit produces
Status: not started

Add `Source/LazAssistantMonitor/AssistantMonitorSync.pas`, registered in the monitor package. Interface uses stay limited to what the public types need. No form unit, no LCL.

The unit takes the mirror log, the phone's acknowledged sequence, and a resume request, and returns the frames to put in the outbox. It does not read the assistant form. `ObserveTurn` remains the producer of `turn_open`, `block_open`, `block_append`, `block_replace`, `block_close`, and `turn_close`. Change `AppendLocked`'s callers in `AssistantMonitorMirror.pas` so a `block_append` longer than 4 KiB is appended as several slices, each with its own sequence and offset, split on a code-point boundary. A `block_replace` is only for a change that is not a suffix; its body over 4 KiB is deferred: the event carries `deferred` and `body_bytes`, and the phone fetches with `block_get` (`ServeBlockGet`). No single event is then large enough for `AppendLocked` to drop.

On the link thread, the session keeps one send cursor: the highest sequence put in the log lane. While the mirror head is past it and the bytes since the last acknowledged sequence are under the credit window, it frames the next event from the mirror and appends it to the log lane. An `ack` advances the acknowledged sequence and calls `TMonitorOutbox.Acknowledge`. A new resume clears the log lane and resets the cursor. The mirror log, not the outbox, is the replay store; the outbox log lane only holds what is inside the window, so the 8 MiB log outbox budget becomes a backstop. If it is ever passed, close the link with `bye` and let the phone resume.

`PumpMirror` stops selecting dirty blocks and stops calling `ReplaceLivePatch`. A status or plan-row change is state, coalesced to the latest value, and does not allocate a content sequence. Do not keep a "sent blocks" copy. The acknowledged sequence is the only sent mark.

Keep the new unit under 1000 lines. If the page JSON in `AssistantMonitorMirror.pas` is only needed for the old push path, leave it until item 7.1 deletes that path. Do not add more page writers.

### 5.2 One resume answer, from the mirror, on the connection thread
Status: not started

`HandleResume` is the only resume entry. It calls the new unit and queues the answer. Remove the fall-through that queues `mmkResume` onto the IDE thread for content. `AnswerResume`, `SendCatchupSnapshot`, and `ServeResumeFromMirror` must not all survive; one answer remains.

Rules for the answer, in order:

- State keys first, including approval when one is active.
- Stream id match and the log holds every event after the phone sequence: reset the send cursor to that sequence and let the slices flow. Nothing else.
- Otherwise: one outline with per-block hashes, the new stream id, and the head sequence, then the send cursor starts at the head. Do not walk older turns. Do not push bodies; the phone fetches the open block and visible stale blocks (item 6.3).
- `commands` on the resume, if present, still get `command_states`. That reply is control, not content.

If the mirror has not observed the open conversation yet, send state and `not_ready`. The phone keeps its cache. Do not send an empty outline or an empty page. The comment in `DeliverOpenScreen` and `SendCatchupSnapshot` about filing an empty page as the conversation is the bug this rule closes. When the form later observes real turns, the mirror appends events and the link thread sends an outline followed by the slices, because the phone's stream id cannot match. It does not need a second resume.

A parked mirror log for another conversation id is the resume source when the phone names that id. If that log was folded, use the outline answer. Do not wipe the phone by sending a blank outline for a conversation the host has not loaded; send `not_ready` for it instead.

### 5.3 State before content, and no truncated plan
Status: not started

Classify frames in the new unit, not with another copy of `OutboundLane` left to drift. Control and approval go to the control lane, other state to the state lane with its key, slices to the log lane, and fetch answers (`block_data`, `image_data`, `plan_data`, turn pages) to bulk.

`PushPlan` stops packing the plan markdown into the plan frame. The plan state value is path, title, running, revision, and the row summaries. The body goes out only in answer to `plan_get`, in 24 KiB pieces. Delete the branch that substitutes "The plan is too large to cache on the phone."

## 6. Phone cache is the screen

### 6.1 Apply slices only, with the cursor
Status: not started

`LanSession` already offers a decoded `event` to `SyncApplier`. That becomes the only content apply. `MonitorCoordinator.incoming` must not apply `patch`, `catchup`, `snapshot`, or `snapshot_page` onto the conversation board. Attach the applier when the stored host id is known, not only after `hello_ok`.

`SyncApplier` already batches to 128 events or 50 ms and commits rows with the sequence in one Room transaction. Keep that. After each commit the applier sends `ack` with the committed sequence, paced to at most one per 250 ms; remove the coordinator's `MonitorEffect.Ack` for content. A gap emits resume and leaves committed rows in place. An event refused by `AccountedEvents` because the inbound budget is full is a gap, not a silent loss: emit resume.

An append whose offset does not match the stored UTF-8 length requests the block (`block_get` with `prefix_hash`) and marks it fetching. While a block is fetching, its appends advance the sequence but are held for that block. When the fetch's last piece arrives with `total_bytes` N, discard held appends that end at or before N and apply the rest in offset order. This stops a streaming block from looping between fetch and mismatch. Other blocks continue.

State frames update a small state row or the existing view fields. They do not advance the content sequence. Approval stays on the control path the session already applies at once.

Do not add this logic to `MonitorCoordinator.kt` or `MonitorViewModel.kt`. A new file next to `SyncApplier.kt` is the right place for the outline reconcile, the held appends, and the state channel.

### 6.2 Open on the cache, including with no link
Status: not started

On launch, and on every reconnect, the conversation screen collects Room flows for the selected host and conversation and renders those rows. It does not wait for `hello_ok`, a point page, or `desktopMatched`. If the database has no row, the screen is the empty state, not a spinner that blocks the cached list.

Disconnect clears the connected chip and disables send, steer, stop, and approval. It does not clear turns, blocks, or the plan summaries already committed. Background and process death use the same rows. The stream id and sequence stored in the conversation row are the resume cursor. `not_ready` shows a note and changes no row.

`watchRepository` becomes the only reader and the coordinator stops holding conversation content. After this item, the applier is the writer and the collector is the reader.

The offline list already reads `ConversationRecord`. Keep that list available with no address configured. Opening a row shows its stored turns and blocks. Stale blocks show their stored body marked as not current. Images whose files are present decode from disk. Missing image bytes stay a placeholder, not a fetch, while the link is down.

### 6.3 Fetch what is on screen, and do not push the rest
Status: not started

After an outline, the phone requests the open block at once, then bodies only for blocks marked stale or deferred that are in the visible range, plus a small prefetch. Keep a cap of two outstanding content fetches so a history fill cannot crowd the bulk lane; the host's control, state, and log lanes already go first after item 4.2. The phone must stop asking for turns the user has not opened.

A turn request is answered with one turn page that the applier commits as rows for that turn only. It does not replace the conversation. Visible-turn tracking (`noteVisibleTurns`) is the trigger. Scrolling back must not re-download a block whose stored hash matches the outline.

Plan body: if the user opens the plan and the stored body is absent or its revision is older than the plan state revision, send one `plan_get` from the stored length when the revision matches, otherwise from 0. Store the pieces as they arrive so a drop keeps the prefix.
