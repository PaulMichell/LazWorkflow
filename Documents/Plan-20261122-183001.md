# Image input and display in Claude turns

Generated by Lazarus Project Assistant.

## 1. Where Claude stands now

Grok turns have three image features. Images can be attached to a message (Attach, paste and drop, through `AttachImageFile` and `AttachImageStream` in `ProjectAssistantForm.pas`). `read_image` copies a project image into the next model turn. `write_image` generates a picture through the profile's image model (`AssistantGrokImageModel`, `AssistantImageAdapters.pas`) and saves it in the project. Attached and generated images are shown in the conversation and sent to the phone (`AssistantMonitorImages.pas`).

Claude turns have none of these:

- `ComposerAttachAllowed` refuses every Claude turn with "Claude Code turns do not attach images." The send path then blocks any message that has image refs.
- `TAssistantClaudeRun.Execute` passes the prompt to `claude -p` as plain text on stdin. That cannot carry an image.
- The Lazarus tools reach Claude through the MCP broker (`AssistantToolBroker.ToolsJsonForScope`). Its catalogue has no `read_image` or `write_image`, and `AssistantMCPProtocol` returns only text in tool results.
- Claude Code's own `Read` tool, allowed outside Chat, can already read a PNG or JPEG in the project, so a Claude turn can look at a project image. The IDE does not show that image in the conversation.

Claude models take images as input. They do not generate raster images: a Claude subscription has no image endpoint. Decision, 2026-11-22: the user does not want Claude turns to borrow another provider's image model, so Claude turns get no `write_image` and no generated pictures. Image output in this plan means showing images that already exist or that a turn saves, and writing text formats such as SVG.

Constraints from the Claude connector hold throughout. Turns run on the subscription; never add `--bare`, `--max-budget-usd` or `--betas`, and never read Claude sign-in files. A turn that has run a tool is not replayed automatically.

### 4.2 Stop offering image generation to Claude turns

Status: not started

Claude turns cannot generate images, and by the decision in section 1 they will not borrow another provider's image model. The IDE should not suggest otherwise:

- The mode instructions sent with a Claude turn still say "Images use write_image" (the Plan-mode directive does, from `AssistantPlan.pas` and `AssistantHarness.pas`). A Claude turn has no `write_image`. For Claude, say instead that it cannot generate images, and that SVG and other text formats use `write_file`.
- The settings form must not offer image output on a Claude profile. If a saved Claude profile already has `image_output` set, ignore it for Claude turns rather than rewriting the user's settings file.
- `AssistantTurnOffersImageOutput` returns false for a Claude turn, so no catalogue or instruction offers `write_image`.

Grok and Codex image output is unchanged. Tests: the Claude Plan, Document and Build instructions do not name `write_image`; the Grok ones still do when image output is on; a Claude profile with `image_output` set does not offer it.
