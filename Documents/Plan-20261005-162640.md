# Assistant connections, skills, and usage

Generated by Lazarus Project Assistant.

Settings stay on four pages: General, Connections, Spelling, and Tests. Model choices live on the selected connection. No connection kind is inserted automatically. Grok, ChatGPT, an OpenAI-compatible endpoint such as OpenRouter, and a Claude account are all optional rows the user adds.

Anthropic does not allow this assistant to offer Claude.ai login or to keep a Pro, Max, Team, or Enterprise OAuth token. The Claude row therefore runs the installed `claude` program, the same shape as the ChatGPT row running Codex. Sign-in stays inside that program. Do not read its credential files, do not set `CLAUDE_CODE_OAUTH_TOKEN`, and do not send those tokens to the Anthropic Messages API. A Claude model inside this assistant's own tool loop is an OpenAI-compatible row pointed at a gateway, not a Claude.ai session.

## 1. Constraints

Touch only the units named on each item. Follow Michell Computing style: PascalCase keywords, 2-space indent, and `Result` assigned on every path. Streamed form fields stay in the unnamed first section. Do not add a trailing `Published` section, and do not prefix streamed controls with `F`.

New static pages and frames go in `.lfm` files. Do not extend `BuildSettingsPages` or `EnsureExtraControls`. Delete those builders when the streamed form replaces them.

A save still replaces only the `assistant` section of `LazWorkflow.json`. Credentials for Codex and Claude stay in those programs' own profiles. An OpenAI-compatible key may be an environment-variable name or a value in that assistant section. Never write a key, token, or Authorization header into a log, a trace, or a usage record.

`##` sections are context. Only a `###` item has a Status line.

## 2. Connection store

The store is `TAssistantConnections` in `Source/LazAssistantTools/AssistantConnections.pas`, loaded by `TAssistantConfig.LoadWithConnections` and `SaveWithConnections` in `AssistantConfig.pas`. `EnsureBuiltinGrok` runs when the section is missing, when no row has `backend` `grok`, when the list would save empty, and when the active id does not resolve. `Remove` refuses a `grok` row and forces the active id back to `grok`. `Source/Tests/AssistantConnectionsTest.lpr` expects that built-in row.

Grok sampling (model, thinking, search, citations, verbosity, max output tokens, approval) is copied onto the global config from the Grok object. Codex already stores model, reasoning, and approval on its own row.

## 3. Providers

### 3.1 Call an OpenAI-compatible endpoint
Status: complete

Add `Source/LazAssistantTools/AssistantCompatibleClient.pas`. Use `HttpsGet` and `HttpsPostJson` from `AssistantHttps.pas`. Register the unit in `Packages/LazAssistantTools.lpk` only if the package does not already compile units from that directory by wildcard. Do not add a Grok OAuth call on this path.

The client takes the connection's base URL, wire, key source, and model. `env` reads the named environment variable at request time and fails with a clear message when it is unset. `stored` sends the saved value. The header is `Authorization: Bearer`. Also send `X-Title: LazWorkflow` when the preset is `openrouter`. Do not log the header.

`ListModels` is `GET {base}/models`. It fills a string list with each `id` and returns the error text on a non-200 or a body that is not a model list. `CompleteOnce` is `POST {base}/chat/completions` with the model, the messages, and `max_tokens` when `MaxOutputTokens` is greater than zero. Do not send Grok reasoning, search, or citation fields on this wire.

Parse usage from the response object when it is present: `prompt_tokens`, `completion_tokens`, and `cost` when that number is present. Missing usage is a successful completion with usage state `unavailable`. A fixture in `Source/Tests/AssistantProviderTest.lpr`, or a new test program next to it, covers one model list, one completion, one usage object that includes cost, and one completion with no usage object. No test opens a socket.

Validation: build

Check: the fixture completion returns the assistant text, the token counts, and the cost. The no-usage fixture returns the text and state `unavailable`.

### 3.2 Call the installed Claude Code program
Status: complete

Add `Source/LazAssistantTools/AssistantClaudeClient.pas`. This is a process wrapper, not an HTTP client and not an OAuth client.

Detect the executable on `PATH` and from the path the user browsed to. Store only that path on the connection, in `Runtime`. Sign-in starts that executable so its own login runs. The assistant does not parse or copy credentials.

A turn runs `claude -p` with `--output-format json` and `--model` set from the connection. Map approval to the program's permission mode when the installed program accepts that flag: ask, accept edits for auto, and bypass for always. If the flag is refused, report that text and do not retry with a stored token.

Read usage from the JSON result when `usage.input_tokens` and `usage.output_tokens` are present. Leave cost empty. A result with no usage object is state `unavailable`. A test feeds a saved JSON fixture and does not require the `claude` binary.

The Claude row does not receive this assistant's tool list, skill bodies, or transcript compactor. The status text on the row says that Claude Code keeps the session.

Validation: build

Check: the fixture parser records input and output tokens and an empty cost. A unit test fails the build if the new unit contains `CLAUDE_CODE_OAUTH_TOKEN` or reads a Claude credential file.

## 4. Settings dialog

`Source/LazAssistantTools/AssistantSettingsForm.pas` and `AssistantSettingsForm.lfm` build the pages in code. `BuildSettingsPages` reparents the flat Grok controls into a scroll box. Spelling is a frame on General. The model list, skill combo, search, verbosity, and token limit sit on the Grok connection.

### 4.1 Stream four pages, with model fields on the connection
Status: complete

`AssistantSettingsForm.pas`, `AssistantSettingsForm.lfm`, `AssistantCodexSettings.pas`, `AssistantCodexSettings.lfm`, and `Source/Tests/AssistantSettingsTest.lpr`.

Replace the runtime page builder with a streamed `TPageControl` named `SettingsPages`. The pages are General, Connections, Spelling, and Tests. There is no Model page. Delete `BuildSettingsPages` and `EnsureExtraControls`.

Connections is a list on the left and one detail frame on the right. The list is every saved row. Buttons under the list are `Add connection…` and `Remove`. Add opens a menu with `Grok account`, `ChatGPT (Codex app)`, `OpenAI-compatible endpoint`, and `Claude account`. None of those items is disabled because a row of that kind already exists. Remove deletes the selected row, including Grok.

The detail always shows Identity (name, kind, `Use for current chat`) and then the groups for that kind:

- Grok: Account (status, sign in, sign out, paste code), Model (model, refresh, reasoning, answer length, max output tokens, live search, citations), Endpoint (API base URL), Permissions (tool approvals), Usage.
- ChatGPT: the existing Codex account fields, then Model (model and reasoning only) and Permissions. No API base URL and no Grok generation fields. Usage says the program did not report counts unless a later item recorded some.
- OpenAI-compatible: Preset (`OpenRouter` or `Custom`), base URL, key source (`Environment variable` or `Stored key`), wire label `Chat completions`, Test connection, Model (id, refresh, max output tokens), Permissions, Usage.
- Claude: executable, Browse, Auto-detect, `Sign in with Claude`, Check, the status sentence from item 3.2, Model, Permissions, Usage.

Choosing OpenRouter fills the base URL and the default env name `OPENROUTER_API_KEY`. Custom leaves the URL editable. The stored-key edit is a password edit. Switching kind does not show the other kind's account fields.

Spelling hosts the existing spell frame, aligned to the page, without a second outer caption. Tests hosts the existing test frame. Both stay streamed.

`AssistantSettingsTest.lpr` opens the dialog, selects each page, and finds the connection list. It does not require a Grok row.

Check: the form resource contains the four page captions and contains no control created by `BuildSettingsPages`. The designer can open `AssistantSettingsForm.lfm`.
