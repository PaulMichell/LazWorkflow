# Offline prompt dictation for the monitor app

Generated by Lazarus Project Assistant.

Add on-device speech-to-text to the existing prompt field in `Source/KotlinMonitorApp`. The user dictates into the prompt, edits the text, and submits only by the existing Send or Steer action. Recognition uses Android's on-device `SpeechRecognizer` and never falls back to a network recognizer.

This is a phone-app change. Do not modify the Lazarus packages, the desktop composer, or the `:protocol` module. Do not change the monitor wire format.

## 1. What is already there

The app is `Source/KotlinMonitorApp`, package `computing.michell.monitor`. UI is Jetpack Compose Material 3. `MainActivity` hosts `MonitorShell`, which shows `ConversationScreen`, `PlanScreen`, or `SettingsScreen`. State is `MonitorViewModel` (`AndroidViewModel`) and `StateFlow<MonitorUi>`.

The prompt is `MonitorUi.draft`, edited by `PromptField` in `ConversationScreen.kt` and stored again on `LanSession.promptDraft` through `updateDraft`. That draft already survives disconnect. It does not survive process death. Configuration changes already keep it, because the Activity `ViewModelStore` retains the ViewModel.

Submit is `sendOrSteer()`. It trims `draft`, encodes with `tryEncodeSend` or `tryEncodeSteer`, then `beginSubmit` clears the draft. It refuses text longer than 65536 characters. A desktop `InsertResult` replaces the whole draft in `applyInsertResult`. `mergeApplied` deliberately keeps the local draft unless that insert path says otherwise.

There is no runtime permission flow, no `RECORD_AUDIO` declaration, and no speech code. The manifest has `INTERNET` for the TLS session to the desktop. Leave that permission in place. Do not use it for recognition, and do not add another copy for speech.

SDK levels in `gradle/libs.versions.toml`: `minSdk` 26, `targetSdk` 35, `compileSdk` 35. On-device `SpeechRecognizer` exists only from API 31. API 26 through 30 must show the feature as unavailable. `app/src/test` is JVM JUnit and already tests pure UI reducers in `MonitorReducerTest.kt`. There is no `androidTest` source set. Do not add Robolectric, Espresso, or a DI framework.

The prompt field is an `OutlinedTextField` bound to a `String`. It does not track the caret. Buttons are text, with no icon library. Do not add a Gradle dependency for icons or speech.

## 2. Design

Keep the change small. Three pieces:

- Pure prompt splicing and a pure dictation reducer, with no Android types, so the existing JVM tests can cover text behaviour.
- A thin on-device engine behind an interface, so the prompt editor does not name `SpeechRecognizer`.
- ViewModel ownership of one recognizer, plus a separate `StateFlow` for dictation. Do not store dictation phase inside `MonitorUi`. `mergeApplied` would drop it or entangle it with catalogue updates.

Offline rule: call `SpeechRecognizer.isOnDeviceRecognitionAvailable` and, only when that is true, `SpeechRecognizer.createOnDeviceSpeechRecognizer`. Never call `createSpeechRecognizer`. Never treat `RecognizerIntent.EXTRA_PREFER_OFFLINE` or `isRecognitionAvailable` as proof of offline recognition. If the on-device service is missing, or the device is below API 31, disable the control and explain why. Do not start a network session instead.

Language is British English, `en-GB`, with `RecognizerIntent.LANGUAGE_MODEL_FREE_FORM` and partial results enabled. One recognition session is one utterance. Silence and platform session limits end that session. The user taps the microphone again for the next segment. Do not restart listening from `onError`, `onResults`, or a timer.

`stopListening()` asks the service for a final result. `cancel()` discards the unfinished session. Those are different actions. Late callbacks after cancel or after a newer session id must not change the prompt.

Significant restructuring is not required. No new architecture, no protocol change, no third-party recognizer.

### Text model

One active session freezes three pieces of the prompt at start: `prefix` (before the caret or selection), `replaced` (the selected text, which dictation will replace), and `suffix` (after the selection). The provisional hypothesis is not part of those three.

Displayed text while listening is `prefix + spaced(hypothesis) + suffix`. The selected text is hidden until cancel or failure restores it. Every partial result replaces that same middle. It is the full hypothesis for this session, not a delta. Never append a partial onto the previous partial or onto the committed prompt.

Spacing, applied to both partials and the final text so the field does not jump at the end:

- Trim the recognised text.
- If `prefix` ends with a non-whitespace character, add one leading space.
- If `suffix` starts with a non-whitespace character, add one trailing space.
- Do not add a space beside existing whitespace, and do not add a leading space when `prefix` is empty.
- An empty hypothesis displays as an empty middle. Do not invent words.

Caret after each partial or final commit is the end of the inserted middle, so the next tap continues from there. The user can move the caret before the next session.

User edits while a session is active:

- If the new text still has the same `prefix` and `suffix` and only the middle changed, keep the anchor and treat the middle as the new provisional. The next partial may replace that middle. That is the recognizer's hypothesis, not a second copy.
- If the user changes the caret only, and it stays in the provisional span, keep listening.
- If `prefix` or `suffix` no longer match, the anchor is stale. Turn the toggle off, cancel the recognizer, ignore later callbacks for that session id, and keep the text the user just typed. Do not restore the old prompt over their edit, and do not splice a later partial into it.

Ending a session:

- There is no Cancel control. The microphone is a toggle. Pressing it while it is on, or a platform silence timeout, turns it off and asks for a final result (`stopListening`).
- Commit that final text and drop `replaced`. If the ending comes back as an error but the provisional middle is non-empty, commit that provisional text. If it is empty, restore `replaced` and say that no speech was recognised.
- A recognition failure with no hypothesis does the same for the text: restore `replaced`, keep everything else, turn the toggle off, and show a short message. Previously committed prompt text must remain.
- Leaving the screen is not a button. Turn the toggle off, call `cancel()` so the microphone releases at once, keep the text already shown in the field, and ignore a late result. Do not snap the prompt back.

A blank partial callback is ignored. It must not clear a hypothesis already shown. A blank final result is "no speech recognised", not a wipe of the committed prompt.

Second session: capture a new prefix, replaced, and suffix at the current selection. With the caret at the end, the first sentence stays and the second is inserted after one space when needed. Example: `Explain how PostgreSQL indexes work.` then `Include examples using spatial queries.` becomes those two sentences separated by a space.

If the composed draft would pass 65536 characters, turn the toggle off, keep the committed sides, drop the provisional rather than exceeding the limit, and put `Text is longer than 65536 characters.` in the right-hand status item. Do not submit. Do not add a row for that message.

### Session and lifecycle rules

Recognizer operations run on the main thread. Create it with the application context from `AndroidViewModel`, never an Activity. Call `setRecognitionListener` before `startListening`. Hold one instance. Do not create another while one exists. `destroy()` it in `onCleared`, and if `ERROR_CLIENT` means it cannot be reused, destroy it and create a fresh one only on the next explicit tap.

Ignore `start` while listening or while a result is still outstanding. A tap while the toggle is off starts. A tap while it is on turns it off and requests the final result. It does not start a second session. After toggle-off, ignore another start until the recognizer is idle. Do not add a Cancel button.

Do not listen in the background. Leaving the conversation tab, opening settings, disconnect handling, and `Activity.onStop` when `isChangingConfigurations` is false turn the toggle off and `cancel()` the recognizer. Keep the draft text already on screen. Do not cancel on a configuration change: the ViewModel and the single recognizer survive. Do not auto-start again on resume. A platform timeout also turns the toggle off. Do not restart listening from that timeout. If the service errors across rotation, treat it as a failed session and recreate the recognizer lazily on the next tap.

`InsertResult` still replaces the draft. If a session is active, turn the toggle off and `cancel()` the recognizer first, then apply the inserted text, so a desktop insert is not merged with a hypothesis.

Send and Steer stay disabled while a session is active or a provisional middle is showing. Dictation must not call `sendOrSteer`. After commit, the prompt is ordinary editable draft text.

Intent extras, and only these: `ACTION_RECOGNIZE_SPEECH`, `EXTRA_LANGUAGE_MODEL` = `LANGUAGE_MODEL_FREE_FORM`, `EXTRA_LANGUAGE` = `en-GB`, `EXTRA_PARTIAL_RESULTS` = true, `EXTRA_MAX_RESULTS` = 1. Read hypotheses from `SpeechRecognizer.RESULTS_RECOGNITION`, first string only. Do not set silence extras in an attempt to hold the microphone open past the platform limit.

## 7. Language model and errors

### 7.1 Handle on-device language support and failures
Status: not started

On API 33 and later, after permission is granted and before `startListening`, call `checkRecognitionSupport` on the on-device recognizer with the same intent. Then:

- `en-GB` in `getInstalledOnDeviceLanguages`: start listening.
- `en-GB` in `getPendingOnDeviceLanguages`: do not listen. Say that the offline English (UK) speech model is still downloading. Do not poll.
- `en-GB` in `getSupportedOnDeviceLanguages` but not installed: explain that the offline model needs to be downloaded, and call `triggerModelDownload` once for that tap. The system may ask the user to confirm. Do not listen until a later tap finds the model installed.
- `en-GB` only in `getOnlineLanguages`: treat as unavailable. Do not use the online language.
- `onError` with `ERROR_CANNOT_CHECK_SUPPORT`: this check is unavailable. Start listening on the on-device recognizer anyway. Still do not switch to the network factory.

On API 31 and 32, skip `checkRecognitionSupport`. It does not exist. Start listening and map language errors as below.

Map codes to short sentences. Never show the integer code.

- Insufficient permissions: microphone permission is required.
- Speech timeout: no speech detected.
- No match: no speech recognised.
- Recognizer busy: speech recognition is busy. Wait and try again.
- Audio: the microphone could not be used.
- Language unavailable: offline English (UK) speech model is not installed.
- Language not supported: offline English (UK) speech recognition is not supported on this device. Leave the feature unavailable after this.
- Network, network timeout, or server: on-device speech recognition failed. Do not retry on a network recognizer.
- Client or server disconnected: speech recognition stopped. Try again. Destroy the recognizer after a client error so the next tap creates one instance.
- Anything else: speech recognition failed.

After an error, the toggle returns to off unless the feature is now unavailable. The right-hand status item keeps the message until the next successful start. No error path clears committed prompt text. Do not add a caption row for these messages.

## 9. Acceptance

The work is done when the microphone toggle is the left control on the existing button row, the status line sits below that row, and its right-hand item shows `Listening…` while the toggle is on. Speech is recognised only through `createOnDeviceSpeechRecognizer`. Partials appear in the prompt field without duplication. Finals become editable draft text. Several sessions can fill one prompt. Committed text is not discarded. The user turns dictation off by pressing the toggle again or by the platform timeout, not by a Cancel button. Send is still explicit. Permission denial and recognition failure use that same right-hand status item. The recognizer is destroyed with the ViewModel, and the catalogue send path is unchanged.

Known limits, to state in the completion summary: devices below API 31 have no on-device API; not every device has an on-device engine or an installed `en-GB` model; sessions end on silence and are not restarted; the platform on-device service is used as documented, with no network fallback in this app; process death still drops an unsent draft, as it does today.
