# Status bar progress phrases

Generated by Lazarus Project Assistant.

While a turn is in progress, the right-hand status is only one action word, the same ellipsis as `Thinking…` (U+2026), and the total elapsed turn time. `FormatElapsedStatus` already appends that clock as `0:12`. The painted text is `Waiting… 0:12`. No other words, counts, or fault text belong on that label.

The progress set is `Waiting…`, `Thinking…`, `Streaming…`, `Running…`, `Steering…`, and `Connecting…`.

When nothing is in progress, the same slot has exactly two labels, with no ellipsis and no clock. `Ready` means a model is connected and the assistant is awaiting a prompt. `Offline` means no model is connected. On the monitor, `Offline` also means there is no valid connection to the IDE. `Not signed in`, `Cancelled`, and `Offline, Re-connecting` are not labels for this slot.

Anything longer is a note on the live conversation at the moment it occurs. The head is the newest position of the live trace, the end the view already follows, not index 0 of the history. `TAssistantTrace.AddNote` already inserts there, before the worked footer. Do not also paint the sentence on the status bar. Do not add a second copy when `aekRecovery` or `PostRecoverySentence` has already added that sentence.

A note at that position must not freeze the live answer. `ApplyLiveAnswerSlice` returns when the last block is a note. Update the answer block that precedes the note. Do not open a second answer after it.

Do not change the footer fitter, the JSON phase token `waiting`, or the wire format. The monitor paints the same status words. It does not invent a second vocabulary. The note travels in the trace the monitor already snapshots.

## 1. Six progress words

`Running tools…` becomes `Running…`. `Steer queued…`, `Steering at next tool gap…`, and `Steering at next model gap…` all become `Steering…`. `Re-establishing Connection` becomes `Connecting…`. `Waiting for first token…` and the bare phase `Waiting` become `Waiting…`, as already decided. `Thinking…` and `Streaming…` stay, but call sites use the same constants so a later edit cannot drift.

`Re-establishing Connection` is recognised and compared, and is not currently assigned. The live reconnect text is the recovery sentence. That sentence leaves the status bar in section 3. The phase during that wait is `Connecting…`.

## 2. The status label

`FormatElapsedStatus` uses a separate reconnect clock when the phase is `Re-establishing Connection` or contains a recovery wait sentence. That is the wrong clock, and it is how a sentence reaches the label. Progress always uses `FTurnStartTick`.

`StreamToken` copies any non-empty snapshot text into the phase. After section 3, a sentence must not take that path. This item makes the label refuse anything outside the six words even if a caller still passes one.

### 2.1 Paint only a progress word and the turn clock
Status: complete

`FormatElapsedStatus` always formats `Phase` plus the turn clock. Delete the reconnect-clock branch. `Connecting…` still shows `0:12` from the turn start, not a second timer.

While `FSending`, `UpdateStatusFooter`, the elapsed timer, and `FillMonitorView` call that function with one of the six constants. If the stored phase is empty or is not one of those constants, use `AssistantPhaseWaiting`. Do not pass a recovery sentence, a plan-agent count, or `Reviewing…` into the activity label.

`ApplyAssistantSnapshots` must not replace `Connecting…` with `Streaming…` or `Thinking…` merely because the answer already on screen is non-empty. Replace `Connecting…` only when new stream text arrives after the wait, or when section 3 sets `Waiting…` at resume. Compare the constant, not `'Re-establishing Connection'`.

`AssistantPhaseIsReconnectWait` may still detect an internal wait. It must not choose the painted clock. Add `Connecting…` to that detector if a caller still needs to know a reconnect is in progress. Do not treat a recovery sentence as a phase.

The monitor `Phase` field is the constant. `StatusText` is `FormatElapsedStatus` of that constant while a turn is sending. Remove the `Plan agent… %d done` and `Reviewing…` branches from `FillMonitorView`. Between turns the monitor uses the same inactive label as the desktop, from section 4.

Done when a sending turn cannot paint a status string that contains a space before the clock. One commit, subject prefix `Assistant:`, containing only this item's files.

## 3. Longer messages become notes

Recovery, plan-run, and build-work sentences are information. They stay in the conversation. They do not become `FStatusPhase`.

Where a note is already added, do not add another. `HandleTraceEvent` already adds one note for `aekRecovery`. `PostRecoverySentence` and `NoteRecovery` also add one. Keep a single note per distinct sentence.

### 3.1 Keep recovery and plan sentences off the phase
Status: complete

`PostRecoverySentence`, `NoteRecovery`, and `StreamToken` must not call `SetStreamPhase` with a sentence. Set one of the six constants, and make sure the sentence is a note at the live head.

Phase for that wait:

- Transport reconnect, a dropped Codex or Claude process, and the old re-establishing path: `Connecting…`. The existing reconnect sentence is the note.
- Credit wait and rate-limit wait: `Waiting…`. The existing sentence, including `Retry at yyyy-mm-dd hh:nn`, is the note. These are waits, not a new connection.
- `Resuming the call.` is a note. The phase returns to `Waiting…` until tokens or tools arrive. Do not leave `Connecting…` up after that note.
- `Retrying the HTTP round.` is a note. The phase is `Connecting…` while that retry is the active wait.
- `Retrying the read-only tool.` is a note. The phase is `Running…`.
- `Handing the tool error back to the model.` is a note. The phase is `Waiting…` until the model continues.
- `Ignoring a paint fault.` and `Ignoring a callback after detach.` are notes only. Leave the phase unchanged.

Plan-run sentences already passed to `PostRecoverySentence` follow the same split. `The plan stopped with items still open. …`, `Resuming the call. The plan still has open items.`, and `Context usage %d%%. Starting a new chat and continuing the plan.` are notes. They do not become the phase. A turn that is actually sending still shows its progress word and the turn clock.

The actor may keep emitting the sentence on the recovery event. It must not emit that sentence as the snapshot status text. The snapshot status text is the constant above. `IsAssistantProgressStatus` still accepts a recovery sentence so an old in-flight snapshot is not stored as an error. The form, on a non-finished snapshot, treats a non-constant status text as a note and does not adopt it as the phase.

Do not rewrite the sentence wording in `AssistantRecovery.pas` or `AssistantPlanRun.pas`.

Done when a reconnect, credit wait, or plan stall shows `Connecting…` or `Waiting…` plus the turn clock, and the sentence appears once as a note at the live head. One commit, subject prefix `Assistant:`, containing only this item's files.

### 3.2 Move footer-only messages into the live trace
Status: not started

`SetBuildStatusFeedback` writes the right-hand label and does not add a conversation note. That label is the progress slot. Stop calling `SetRightText` from that helper.

Each current caller injects its sentence with `AddNote` on the live trace when a trace exists, or `SetCurrentSystemNote` only when no live trace exists. One note per distinct sentence. Do not clear a sending turn's progress phase.

Sentences that move:

- `Working on: <title>`
- `Plan agent: starting…`
- `Plan agent: package %d…`
- `Work interrupted — item still in progress.`
- `<title> → complete` and `<title> → complete (auto)`
- `Plan run ended: …`
- `Could not mark the item blocked: …`

- `Plan has unsaved edits; review before using Done.`
- `Auto-complete failed: …`
- `Removed from the available list. The file was kept.`

`Plan agent… %d done` is the between-turn label in `UpdateStatusFooter` and `FillMonitorView`. It is not a progress phase. When the completed count changes, add one note such as the existing package line. Between turns, the right label is `Ready` or `Offline`, not a count.

`Reviewing…`, and `Compile…` / `Build…` painted by `ReviewProject` before the model turn, are not turn progress and have no turn clock. Do not paint them on the progress slot. Leave the inactive label from section 4 until `SetSending` starts `Waiting…` and the turn clock. The IDE compile is already visible in Messages. Do not add a second clock.

`CompilerFinished` paints `Compile OK (%d warn)`, `Compile failed (%d err)`, or `Cancelled`, then calls `UpdateStatusFooter`. Do not paint those on the slot. The footer refresh is the inactive label. `StopStream` currently paints `Cancelled` after that refresh. Do not. The existing `*Stream cancelled.*` note is enough.

`ApplyLiveAnswerSlice` must still update the answer when a note is the last block. A build-work note during a live turn must not freeze the answer.

Done when none of those sentences are passed to `SetRightText` or `SetStreamPhase`, each appears once as a note when it occurs, and a sending turn keeps its progress word. One commit, subject prefix `Assistant:`, containing only this item's files.

## 4. Inactive labels

`Ready` is already the desktop word when a model can be used and no turn is sending. The negative word is `Not signed in`. The monitor repeats that pair in `activityCaption`, and paints `Offline, Re-connecting` when a turn was running and the IDE link is gone.

A model is connected when the existing desktop test passes: Codex has a runtime and a model, Claude has a runtime and a model, or the Grok account is signed in. Do not require a live Codex or Claude process while idle. Those backends connect per turn. Awaiting a prompt means no turn is sending and the plan agent is not in a turn. Section 3 owns the plan-agent count; this section owns the word left behind.

A valid monitor connection is `LinkPhase.Live` and not disconnected, the same live check `connectionLabel` already uses. Anything else is no connection to the IDE. The left-hand connection word (`live`, `connecting`, `disconnected`) stays. This section changes the right-hand status slot only.

### 4.1 Show Ready or Offline when nothing is in progress
Status: not started

Declare `AssistantStatusReady = 'Ready'` and `AssistantStatusOffline = 'Offline'` next to the phase constants. No ellipsis. No clock.

`UpdateStatusFooter` and `FillMonitorView`, when no turn is sending, set `Ready` if the model test passes and `Offline` otherwise. Replace `Not signed in`. Do not append a clock. `View.SignedIn` stays the Boolean the monitor already reads. The status string is `Offline`, not a paraphrase of that Boolean.

On the phone, `activityCaption` uses `Offline` when `signedIn` is false, not `Not signed in`. `hostTranscriptIdle` treats `Ready` and `Offline` as idle, and still treats `Not signed in` as idle so an old desktop snapshot does not wipe the conversation. When the link is not a valid IDE connection, the right-hand activity label is `Offline` even if the last host status was `Ready` or a progress word. Do not paint `Offline, Re-connecting`, and do not invent a reconnect clock on the phone while the IDE link is invalid. `displayInterrupted` must not replace the status slot. A reconnect sentence, if one is still needed, is a note, not that label.

`strings.xml` `monitor_not_signed_in` becomes `Offline` if a layout still reads it. The activity path uses the literal in `activityCaption`; change that literal too. `monitor_ready` stays `Ready`.

`MonitorReducerTest.kt` asserts `Ready` for a signed-in idle view, `Offline` for a signed-out idle view, and `Offline` for the interrupted-link caption. Remove the `Offline, Re-connecting` assertion.

Done when an idle desktop with a model shows `Ready`, an idle desktop without one shows `Offline`, and a monitor with no live IDE link shows `Offline` in the status slot. One commit, subject prefix `Assistant:`, for the desktop strings, and one `Monitor:` commit for the phone label and its test.
