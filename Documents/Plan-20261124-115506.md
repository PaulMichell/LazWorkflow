# Generate project images through the ChatGPT connection

Generated by Lazarus Project Assistant.

Enable a user signed in through LazAssistant’s ChatGPT/Codex connection to request a still image, save it at an approved project-relative destination and see it in the conversation. Use the existing subscription connection and project image framework. A separate OpenAI API key would change the authentication and billing model and is outside this plan.

## 1. Establish the subscription transport contract

### 1.1 Qualify the installed Codex app-server
Status: complete

A repeat signed-in turn through the production client retrieved a 1,007,867-byte artifact and verified its PNG signature. [Sanitized qualification record](CodexImageGenerationQualification.md)

Use AssistantCodexQualification and the installed server’s protocol schema to identify its version, native image-generation capability, enablement settings and result format. Verify with a signed-in test turn that the IDE can retrieve final image bytes or a documented local artifact. Record sanitized event names, item and turn identifiers, result fields and cancellation behavior for a regression fixture. Exclude credentials and image payloads from diagnostics. ChatGPT’s ability to draw in another client does not establish this contract. If the server exposes no usable result, record the missing protocol support and supported upgrade if known before enabling the feature.

## 2. Connect generation to the project image workflow

### 2.1 Gate the offer and reserve the destination
Status: complete

Extend the capability decision behind AssistantBackendCanDraw and AssistantTurnOffersImageOutput with the qualified Codex capability and profile preference. Apply the same decision to model instructions, native tool availability and broker execution. Enable project image output in Plan, Document and Build for eligible parent turns. Exercise Inspect, Chat, subagents and older server versions as denied cases. Keep SVG on the text-document path.

Use the existing write_image prompt and destination convention. In AssistantTools and AssistantToolBroker, factor out the existing project-path, containment and overwrite checks so approval covers the actual final destination. If the protocol exposes generation only as a model-invoked native tool, let the destination request return before generation and correlate its pending save with the native result. Avoid waiting inside a broker callback for the same turn to advance. Invoke generation once per request.

### 2.2 Collect and validate the native result
Status: complete

Handle the qualified completion event in AssistantCodexClient and AssistantCodexRun. Normalize its result into TAssistantGeneratedImage. Reuse AssistantImageAdapters’ existing image_generation_call parser only if the verified payload matches. For a file result, read only a server-owned artifact from the documented output location after checking resolved-path containment. Bound input size before reading or decoding. Verify the image with the existing acceptance and decoding routines and check its actual format against the destination extension.

### 2.3 Save and publish the image once
Status: not started

Use the shared image writer to commit validated bytes atomically and publish the saved image through the current conversation, preview and phone-monitor workflow. Return the actual relative path only after the save succeeds. Match completions to the originating thread, turn and request. Ignore duplicate or late events after cancellation and discard pending state on disconnect. Preserve any prior destination on failure and report whether generation, retrieval or saving failed.
