## 2. Styled list

### 2.1 Clamp the selection anchor when the item count shrinks
Status: complete

Confirmed in `Source/LazStyledText/StyledList.pas`. `SetItemCount` clamps `FItemIndex` and resizes `Selected`, and never changes `SelectionAnchor`. `SelectItem` then writes `Selected[Position]` from `Min(SelectionAnchor, Index)` to `Max(SelectionAnchor, Index)` with no upper bound. `MouseDown` and `KeyDown` both pass the shift state into `SelectItem`. After a multiselect list shrinks, Shift-click or Shift+arrow can write past the array.

No form sets `MultiSelect`. It defaults to false, so this is not on a current screen. The property is published, so fix the control anyway.

In `SetItemCount`, set `SelectionAnchor` to `-1` when it is no longer inside `0 .. Value - 1`. In the Shift loop, do not write `Selected[Position]` unless `Position` is inside `Selected`. Leave single-select and Ctrl-click behaviour alone.

Check: on a multiselect list, select item 99, reduce the count to 10, then Shift-click. The click must not raise, and the selection must stay inside the new count.

## 3. Markdown viewer

### 3.1 Refuse to save over a newer disk copy
Status: complete

Confirmed in `Source/LazAssistantTools/AssistantMarkdownForm.pas` and its form resource. `WatchTimer` runs every 750ms after a successful load. If the file age changes while the editor is dirty, it sets `FPendingDiskReload` and calls `UpdateStatus`. `UpdateStatus` shows `Modified` whenever `FDirty` is set, so `Disk changed (local edits kept)` cannot appear while local edits exist. `SaveToDisk` writes `SourceMemo.Lines` without reading that flag, then clears it. Save and the close-and-save prompt both call `SaveToDisk`.

Before `SaveToFile`, if `FPendingDiskReload` is set because the file still exists and its age differs, do not overwrite. Ask whether to overwrite, reload and discard local edits, or cancel. Write only after an explicit overwrite. Show a status that names both the local edits and the disk change.

A missing file already gets `Deleted on disk` after `UpdateStatus`. Saving that buffer may recreate it. Do not treat deletion as a newer-copy conflict, and do not reload over dirty text without a yes.

Check: edit a loaded Markdown file, change the same file on disk, wait for the watcher, then Save. The save must stop until the user chooses. The status must not say only `Modified`.

## 4. Assistant Git

### 4.1 Check explicit commit paths against the package
Status: complete

Confirmed in `Source/LazAssistantTools/AssistantTools.pas` and `AssistantGit.pas`. A package `add` rejects each path that fails `CanStage`. A package `commit` only inspects `git diff --cached --name-only -z`. `CommitPathsAccepted` checks the shape of paths after `--`, not package scope. `git commit -m … -- path` records the working-tree content of a tracked path even when that path is not staged, so an out-of-package file is invisible to the cached-diff check. That Git rule was not executed in this pass; the missing check is in the wrapper.

When the target is a package and the command is `commit`, walk every argument after `--` and refuse any path that fails the same `CanStage` test used for `add`. Keep the staged-index check. Do not allow `-a` or any other commit option.

Check: from a package target, `commit -m test --` plus a tracked, modified file outside that package and `Documents/` must be refused before Git runs. An in-package path must still commit.

### 4.2 Pass explicit Git filenames as literal pathspecs
Status: not started

Confirmed in `Source/LazAssistantTools/AssistantGit.pas`. `CommitPathsAccepted` and the `add` check reject `*` and `?`, but not brackets. `RunAssistantGit` does not pass `--literal-pathspecs`, and it strips `GIT_*` from the environment, so a user setting cannot close the hole. Git's default pathspec is a glob, so `file[1].pas` also matches `file1.pas`. That match was not executed here.

For `add` and `commit`, insert `--literal-pathspecs` on the Git process before the user arguments, in the same place as `--no-pager`. Keep the existing `*` and `?` refusal so the caller cannot ask for a glob. Do not reject `[`, or a real bracketed filename could not be named. Magic pathspecs already fail the leading-colon check.

Check: a file named `file[1].pas` stages or commits only itself, and a sibling `file1.pas` is not included. `file*.pas` is still refused.

## 5. Repository patches

### 5.1 Repair create and delete headers in a partial patch
Status: not started

Confirmed by tracing `BuildGitPartialPatch` in `Source/LazRepositoryTools/GitDiffPatch.pas`. Any selected change copies the file's meta lines unchanged, including `new file`, `deleted file`, and `/dev/null`. `GitDiffView` calls this for both stage and unstage. The existing partial-patch test covers an ordinary tracked edit, not a creation or deletion.

A partial unstage of a new file turns unselected additions into context, so the patch has old-side lines while the headers still say `new file` and `--- /dev/null`. That is not a valid creation patch.

A partial stage of a deletion does not keep the unselected lines as context. It drops them, then still emits `deleted file` and `+++ /dev/null` for a hunk that only removes the selected lines. Git may reject that patch, or delete the whole file if the short hunk matches. Either result is wrong.

Buffer the hunks for the file before writing its headers. If the emitted patch still has content on a side that the original headers called `/dev/null`, drop `new file` or `deleted file` and point that side at the real path. Keep those headers only when the emitted patch really creates or deletes the whole file. Leave ordinary partial hunks unchanged. The caller in `GitDiffView.pas` can stay as it is.

Extend `TestPartialPatches` in `Source/Tests/RepositorySafetyTest.lpr` with one partial new-file unstage and one partial deleted-file stage. `git apply` must accept the patch, and the index must contain only the selected lines.

## 6. Spell memo

### 6.1 Insert a tab when WantTabs is set
Status: not started

The handler defect is confirmed in `Source/LazWorkflowCommon/SpellMemo.pas`. `UTF8KeyPress` returns early for `#9` only when `WantTabs` is false. When it is true, Tab fails `UTF8Key >= ' '` and is not inserted. `KeyDown` also has no `VK_TAB` case, which is how a typed Tab arrives. `TCustomStyledText` already inserts `#9` from `VK_TAB` when its own `WantTabs` is set; match that.

The planned diff-editor check was wrong. `DiffEditor` is a `TSynEdit`. Every current `TSpellMemo` sets `WantTabs` false: the composer and the commit message editor. The property is published, so the control should still honour it.

Handle `VK_TAB` in `KeyDown` when `FWantTabs` is true: insert a tab, set `Key` to 0, and exit. Also insert `#9` from `UTF8KeyPress` when `FWantTabs` is true, then clear `UTF8Key`. When `WantTabs` is false, leave both keys unchanged so focus can still move. Do not change `GetDialogCode`.

Check: a `TSpellMemo` with `WantTabs` true inserts a typed Tab at the caret. The commit message editor and the assistant composer, which set it false, still do not.
