# Code review: bugs, simplifications, and optimisations

Generated by Lazarus Project Assistant.

This pass reviewed the assistant skill and prompt path, file-drop handling, project-path checks, and the hot spots in the largest units (`ProjectAssistantForm`, `AssistantTools`, `AssistantSkills`, `AssistantHarness`, `AssistantService`, `AssistantImages`, `GitService`). It is not a line-by-line audit of every repository or spelling unit. Items below are ones that should be changed, in priority order inside each section.

## 1. Bugs

### 1.1 Finish every GTK file drop

Status: complete

`GtkFileDropReceived` in `ProjectAssistantForm` returns without `gtk_drag_finish` when the selection has no URI list, or when the user-data pointer is not the form. GTK then keeps the drag active. Finish the drag on every exit, including the empty and rejected cases.

### 1.2 File drop onto the input controls is GTK3-only

Status: not started

`FormCreate` sets `AllowDropFiles` and `OnDropFiles` on the form. The comment says a drop still lands on the child under the pointer, so `ArmControlFileDrop` arms the input panel, strip, and memo. That arming exists only under `{$IFDEF LCLGTK3}`. The other branch does nothing. On Qt, Win32, and Cocoa, a drop on the memo does not reach the form handler.

Before adding more widgetset code, check whether the current LCL already delivers `OnDropFiles` for a drop on a child. Use that if it does. Add a native arm only where the LCL does not, and name the facility that was checked.

### 1.3 GTK drop arming keeps destroyed controls

Status: not started

`ArmedDropControls` is a unit-level list. Controls are added when armed and never removed. `FormDestroy` does not clear it, and nothing frees the list. After the assistant window is destroyed and opened again, a reused pointer can be treated as already armed, so the new input controls never receive drops. Remove the control on destroy, and free the list when the last form goes away.

## 2. Simplifications

### 2.1 One installed-skill path

Status: not started

Removal is supposed to forget a skill even if the file remains. The grid and prompt already use the installation list, but the old discovery path is still in the tree and still called.

`TAssistantService.RebuildSystemPrompt` still calls `ApplyDeclaredSkillModes` and `RememberDeclaredModes` on every prompt. Both are now stubs. `SkillDeclaredModes` still resolves a name through the project `.assistant/skills` tree. `ListDiscoveredSkills` and `SkillSearchRoots` still scan that tree, but the product list no longer uses them.

Delete the stubs and the unused scan, or make `ResolveSkillFile` refuse a project root. A later edit must not be able to put a directory scan back into the prompt by calling the old routine.

### 2.2 Move the GTK drop out of the main form

Status: not started

`ProjectAssistantForm` is the chat, plan runner, footer, and the GTK drag target in one unit. The drop handler, target entry, and armed-control list are a separate platform concern. After 1.2 decides what the LCL already does, put whatever native arming remains in a small unit so the form only implements `OnDropFiles`.

## 3. Optimisations

### 3.1 Do not reread every skill file on every prompt

Status: not started

`BuildSkillsSection` calls `ListGuidanceDocuments` for every system prompt. That reads each installed file to get the document name, then reads it again for the description and when-to-use line. Tagged bodies may read the same files a third time. Cache the catalog text until the installed list or a file age changes. Keep the existing one-file body cache, but key it so two tagged skills do not evict each other.

### 3.2 Do not scan every skill file on a name miss

Status: not started

`SkillFilePath` returns the stored path for an exact key, then reads every stored skill file and compares front-matter names. `read_skill` of an unknown name pays that scan. After `AdoptSkillDocumentNames`, the stored key is the document name, so the scan is only a fallback for an old key. Resolve the exact key, and do not open every file when the name is absent.
