# Image generation that draws

Generated by Lazarus Project Assistant.

The current image path is not fit for purpose. A ten-minute icon request never called an image model. Every `write_image` returned in 0.0s. The time was reasoning, project searches, and three subagents.

Response image part is the default, and it cannot draw. The tool only saves a turn-local id. The host never registers an image-generation tool, so a chat model never produces that id. `read_image` attachments are not generated images. The prompt still says to create images with `write_image`. The model spent the turn trying to obey that sentence with a save-only tool. Build mode allows 80 rounds and does not stop the same failure twice.

Tool prompt is not a fix. It posts the chat model id to `/images/generations`. The chat picker already drops ids containing `imagine` or `image-gen`, so an image model cannot be selected as the assistant. The Ecology Survey Scheduler attempt was this trap, not a slow generator.

This plan replaces both delivery modes with one draw-and-save call. The chat model stays the assistant. `write_image` calls a separate image model on that connection's image endpoint. Grok Imagine is the Grok default, not the only model. Any other image model the connection can call is chosen the same way: the user sets its id, and that backend's request builder posts it. The model-facing tool does not change.

A chat model that sometimes emits an image part is not a second switch. That is the path which just failed. Do not revive it. A later provider that can only draw that way needs a new adapter behind this same tool, not a delivery combo.

This work stays in LazWorkflow / LazAssistantTools. Do not add image-generation code to Ecology Survey Scheduler. Keep the existing path sandbox, magic-byte check, overwrite rule, and size ceiling. Path checks stay before any network call.

Out of scope: video, image editing, more than one image per call, and deferred polling. A program icon is one synchronous draw.

## 1. One image model, not a delivery mode

The profile no longer chooses how pixels arrive. It chooses whether drawing is on, and which image model draws. The writer stays one function. The backend chooses the request body.

### 1.1 Drop delivery from the profile
Status: complete

Remove `ImageDelivery` from the settings form, the tool schema, and the writer branch. Stop writing `image_delivery`. On load, ignore a stored value so old connections still open. `ImageOutput` remains the switch, default false. A capable turn is still Build only. Plan and Document do not offer the tool.

### 1.2 Store the image model beside the chat model
Status: complete

Add an image-model string on the connection, separate from `Model`. It holds whatever id that endpoint accepts, not only an Imagine id. Turning image output on for a Grok connection with an empty image model sets `grok-imagine-image-2.0`. One named constant owns that Grok default. OpenAI-compatible connections, including OpenRouter, have no default: the user sets the id (`gpt-image-1`, `dall-e-3`, a Flux id, or any other id that base accepts). Claude and Codex have no image endpoint in this host, so they get no default and cannot draw. The chat picker keeps hiding media ids. The image field is not filled from the chat model, and it is not limited to ids the chat picker shows.

### 1.3 Let the backend build the request
Status: not started

Keep one `RequestProfileImage` entry. Split the JSON by backend. Grok posts `model`, `prompt`, `n` of 1, `response_format` `b64_json`, and `aspect_ratio` only for a documented ratio. It does not send `size` or `quality`. OpenAI-compatible posts `model`, `prompt`, `n` of 1, and `response_format` `b64_json`. It sends `size` only when it can map the optional shape to a pixel size that builder knows. It does not send `aspect_ratio`. Claude and Codex fail before any post: this connection has no image endpoint. An empty image model fails the same way, naming the missing setting. Adding a provider is a new builder plus the shared writer, not a new tool.

## 2. Settings

The user must be able to see which model will draw, including a model that is not Imagine. The current hint says turning the checkbox on keeps the current model. That hint is the old contract.

### 2.1 Replace the delivery combo with an image-model field
Status: not started

On the connection page, keep one checkbox, captioned so it means this connection may draw. Replace the Delivery label and combo with an editable image-model control. Grok offers `grok-imagine-image-2.0` and `grok-imagine-image`, and still accepts another id typed in. OpenAI-compatible offers an empty field the user can type. Claude and Codex leave the control disabled and say this connection cannot draw. The hint says the chat model is not the image model. Enabling the checkbox on a Grok row fills the default when the field is empty. Disabling the checkbox does not clear a stored id.

## 3. The draw call

`RequestProfileImage` is the only network path. It lives in `AssistantImageAdapters`. The writer does not build vendor JSON.

### 3.1 Post the stored image model
Status: not started

The body uses the stored image model, never the chat model. An optional tool shape is translated by the builder in item 1.3. A shape that builder cannot express is omitted, not a failed draw, so a Grok ratio does not make an OpenAI call fail and an OpenAI pixel size does not make an Imagine call fail. Do not invent a size the endpoint may reject. An empty image model, a backend with no builder, or a non-HTTPS endpoint fails before the post. Bound the HTTP call to about a minute so a hung endpoint cannot occupy the Build round budget.

### 3.2 Accept one image and fail closed
Status: not started

Both builders share the images-endpoint parser. Require exactly one image. Prefer `b64_json`. If the body has only a temporary `url`, download that URL once with the same bearer and then stop. A missing image, a bad status, or a download failure returns the status and a short body, plus a line that says not to retry. Do not leave the model to fetch the URL. Do not fall back to the chat model or to a response-part harvest. A test hook supplies fixture bytes. No live call in tests.

## 4. The tool the model sees

The schema and the prompt must describe the same action. The last failure was those two texts contradicting each other. The model must not have to know which image product is configured.

### 4.1 Make write_image draw and save
Status: not started

Required arguments are `path` and `prompt`. Optional arguments are `overwrite` and `shape`. Remove `image_id`. `shape` is a short hint such as `1:1`. Omit it to let the image model choose. The description says this call draws one still image with the connection's image model and saves it. It is not a copy of a `read_image` attachment. Prefer PNG unless the user names another allowed extension. The success text keeps the Wrote line, path, byte size, width, height, and MIME type, and adds the image model id so the user can see which model ran. Attach the saved image on the tool result so the chat shows it without a later `read_image`.

### 4.2 Tell the model to call once
Status: not started

Replace the image-output prompt section. It says: call `write_image` once with a short prompt and a project path; a few reads of existing art are enough when the user asked for a match; do not search the assistant source; do not spawn a subagent to draw; do not invent another image tool; do not pick or name an image model in the call; do not claim a file exists unless the result starts with Wrote. Exact pixels may differ across models. Do not retry for that. Subagent sessions do not receive `write_image`.

### 4.3 Stop a repeated failure in the host
Status: not started

After one failed `write_image` in a turn, a later call in that turn does not post again. It returns the first error and tells the model to stop and report that error. Clearing happens at turn start. A prompt line is not enough. The Ecology turn retried the same failure until it was cancelled.

## 5. Verification

Fixture tests only, except one hand check. Update the tests that still assume response-part ids or that the chat model is the image model: `AssistantConnectionsTest`, `AssistantGeneratedImageTest`, `AssistantWorkTargetTest`, and the harness prompt check.

### 5.1 Cover Grok and another image model without a network
Status: not started

Flag off: the tool is absent, and a call is an unknown tool. Flag on: the schema requires `prompt`, has optional `shape`, and has no `image_id`. A Grok mock post of a fixture PNG writes the file. The posted JSON contains `grok-imagine-image-2.0`, not the chat model, and has no `size`. An OpenAI-compatible mock with a different image model posts that id, has no `aspect_ratio`, and does not post the chat model. The result names the image model that was posted. Claude or Codex with the flag on does not post. Refuse a missing image model, a missing prompt, path escape, a symlink out of the project, bad magic bytes, overwrite without the flag, and any call in Plan or Document mode. An inapplicable shape is omitted and the draw still proceeds. A second call after a failed draw does not post. A subagent tool list has no `write_image`.

### 5.2 Check one icon by hand
Status: not started

With a Grok connection, image output on, and the default image model, ask for a PNG program icon. Confirm one image request, a real PNG at the requested path, `grok-imagine-image-2.0` in the tool result, and the picture shown in the chat. A forced bad image model must fail once and must not start a search loop. A second live provider is not required. Item 5.1 is the check that another image model is posted unchanged.
