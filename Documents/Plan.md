# Lazarus Assistant Plan Format

Generated by Lazarus Project Assistant.

Work packages use a `##` heading. Actionable items use a `###` heading and a `Status:` line so Build mode can scan this file for TODO tiles. `##` headings are context only and have no status. Other Markdown under the project is not an assistant plan.

Status values: `not started` | `in progress` | `complete`

## 1. Overview

The Plan list and the Build progress list currently treat every `*.md` file, and every `##` or `###` heading, as plan material. That pulls notes, reviews, and preamble sections into the UI, and `FormatPlanSectionTile` adds a second `1.` `2.` `3.` in front of headings that are already numbered.

After this work, an assistant plan is a file whose first non-empty line is a level-1 title and whose next non-empty line is exactly `Generated by Lazarus Project Assistant.` The Plan list shows that title with the project-relative path in parentheses. The progress list shows every `##` heading as context, with no status suffix, and shows a `###` heading only when the next non-empty line is a status line. Heading numbers in the file are the only numbers; the list must not add its own.

Do not bulk-rewrite `Documents/*.md`. Notes, reviews, and the user-guide PDF/ODT stay as they are and simply drop out of the plan list. Do not accept the old template line `Generated by Project Assistant (Plan mode).` The active file for this work is `Documents/Plan.md`, which already uses the new identity line. An active-plan path that fails recognition stays in config, but the UI says it is not a recognised plan and does not invent todos from it.

Until this work lands, the current scanner still treats these `##` headings as tiles. That is the behaviour being replaced, not a reason to put `Status:` under `##`.

Success looks like this:

- Plan list contains `Lazarus Assistant Plan Format (Documents/Plan.md)` and does not contain `Documents/Bug-Review.md`, `Documents/ChatGPT Review.md`, or other notes.
- Progress list shows `1. Overview` and `2. Recognise assistant plans` with no status, and shows `2.1 … — Not started` only for `###` items that have a status line.
- Start, Done, Reset, Work on this, and Work on plan ignore `##` rows and never write a status line under them.
- New Plan, Plan-mode prompts, and the plan subagent emit the same format.

## 2. Recognise assistant plans

Listing is a head scan, not a whole-file search. A guide that quotes the generator line in its body must not become a plan.

### 2.1 Add the identity reader
Status: complete

In `Source/LazAssistantTools/AssistantPlan.pas`, add a constant for the canonical line, including the trailing period from the agreed example:

`Generated by Lazarus Project Assistant.`

Add `IsAssistantPlanGeneratedLine` and `TryReadAssistantPlanIdentity`. Recognition is positional:

- Read only the start of the file (first 32 lines, or the first 8 KiB). Strip a UTF-8 BOM from the first line. Ignore blank lines.
- The first non-empty line must be an ATX level-1 heading (`#` plus a space, not `##`). The title is the trimmed text after that marker.
- The next non-empty line, trimmed, must be the canonical generator line. Also accept the same text with the trailing period omitted, so the prose form matches. Matching is case-sensitive. Do not search the rest of the file.
- Any other shape, including the old `Generated by Project Assistant (Plan mode).` line, is not a plan.

Add `TextIsAssistantPlan` for an in-memory body, using the same head rule. `LooksLikePlanMarkdown` in `ProjectAssistantForm.pas` should call that instead of the current length / `##` / `Status:` heuristic, so a chat reply is auto-saved only when it is already a recognised plan.

## 3. Progress list

`ScanPlanSections`, `FormatPlanSectionTile`, `SetPlanSectionStatus`, and `GetPlanSectionBody` in `AssistantPlan.pas` are the progress model. `RefreshBuildTodos`, `SelectedBuildSectionIndex`, `FindNextIncompleteBuildSection`, and `BuildWorkOnSelectedPackage` in `ProjectAssistantForm.pas` must follow it. There is no second scanner.

### 3.1 Scan context headings and status items separately
Status: complete

Extend `TPlanSection` with `HeadingLevel`, `Actionable`, `BodyLastLine`, and `ParentTitle`. Update the unit comment that still says a section is one `##` work package.

Scan ATX headings only. Require a space after the hashes. Ignore level 1 (the document title) and level 4 or deeper (body).

- Every level-2 heading is a context row. `Actionable` is false. Do not display or count a status line under it, even if one is present. Do not treat it as not-started work.
- A level-3 heading is actionable only when its first non-empty line, before the next heading of level 1–3, is a status line. Blank lines may sit between the heading and `Status:`. Prose before `Status:` means the heading is a note and is omitted. Keep the existing status parser, including `**Status:**` and the `todo` / `wip` / `done` aliases.
- Do not add omitted notes to `Sections`. Still record their heading line as a body boundary so the previous row's `BodyLastLine` stops before them.

`GetPlanSectionBody` uses `HeadingLineIndex` through `BodyLastLine`, not "the next object in `Sections`". Otherwise a note heading between two items would be swallowed into the work prompt.

`SetPlanSectionStatus` refuses a section that is not actionable, with an error that status belongs on a `###` item. It must not insert `Status:` under a `##` heading.

### 3.2 Render the progress list without a second number
Status: complete

`FormatPlanSectionTile` today does `Format('%d. %s — %s', [Index + 1, Section.Title, StatusLabel])`. Remove that index. Context rows show the heading text alone (`2. Recognise assistant plans`). Actionable rows show an indent, the heading text, and the status suffix (`  2.1 Add the identity reader — Not started`). Do not strip numbers out of the heading, and do not invent numbers when a heading has none.

Keep a 1:1 row invariant: `BuildTodoList` items match `BuildSections` order, including context rows and excluding notes. Placeholder rows such as `(No active plan…)` are added only when `BuildSections` is empty, as today.

`RefreshBuildTodos` counts and auto-selects only actionable items. Prefer the in-progress actionable item, then the first not-started one. Never land the default selection on a `##` row. Restore the previous selection by `HeadingLineIndex` rather than a raw list index, so a newly inserted section does not move Start/Done onto another item.

Replace the label and empty-list copy that says todos are scanned from `##` headings. Empty means there is no `###` item with a status line. The summary counts (`not started`, `in progress`, `complete`) ignore context rows.

On GTK/Qt, confirm the indent is visible. If the listbox trims leading spaces, prefix actionable rows with `· ` instead of spaces.

### 3.3 Keep work actions on actionable indexes
Status: complete

`SelectedBuildSectionIndex` returns -1 when the selected row is missing or not actionable. Start, Done, Reset, Work on this, double-click, and `SeedPromptFromSelectedWork` already stop on -1; change their message from "work package" to an actionable item, and say so when a `##` row is selected.

`FindNextIncompleteBuildSection` must require `Actionable` and must stop treating `pssUnknown` as the next job. A context row with unknown status must not be started by Work on plan.

`BuildWorkPrompt` names the parent `##` title (`ParentTitle`) as section context and the `###` title as the item to implement. The section body remains the item only, from its heading through `BodyLastLine`.

Auto-complete in `TryAutoCompleteBuildWork` already calls `SetPlanSectionStatus` with `FBuildWorkSectionIndex`. That stays valid while the plan text is unchanged, which the acceptance check already requires. No new status write path.

## 4. Prompts and the new-plan template

The format is easy to miss because it is copied in several prompts. One shared string in `AssistantPlan` should be the only wording. `AssistantHarness` can use that unit; it does not create a cycle.

### 4.1 Replace the new-plan template
Status: complete

`DefaultNewPlanMarkdown` still writes `Generated by Project Assistant (Plan mode).` and puts `Status:` under `## 1. Overview` and `## 2. First work package`. Replace it with the identity line, a short preamble, numbered `##` sections with no status, and one numbered `###` item whose next non-empty line is `Status: not started`, followed by the notes. `PlanNewButtonClick` already calls this helper; it needs no second template.

Authoring order for every generated plan:

- `# Title`
- `Generated by Lazarus Project Assistant.`
- `## 1. Overview` with prose and no status line
- `## 2. …` with prose and no status line
- `### 2.1 …` then `Status: not started`, then the notes

Section numbers are `1.` `2.` `3.` Item numbers are `1.1` `2.1`, with no extra numbering scheme.
