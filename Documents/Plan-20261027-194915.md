# Overview gutter on Wayland

Generated by Lazarus Project Assistant.

The right-hand overview on `TGitDiffView` is missing on the first show under Linux GTK3 and Qt5. Windows shows it immediately. The cause is when the overview's child window is created, not the gutter width, the colours, or the diff providers.

Do not patch SynEdit and do not add GTK or Qt calls. The fix is to create that child window only after the host form has been mapped, then leave the existing refresh path alone. No timer, no widgetset `{$IFDEF}`, and no new streamed controls.

## 1. What fails

`TSynGutterLineOverview.Paint` is empty. The strip is a private `TSynChildWinControl` (`FWinControl`) parented to the SynEdit. SynEdit only positions it from `TSynGutterLineOverview.DoResize`, and that method returns immediately unless `SynEdit.HandleAllocated` and the part is visible. `TSynGutterBase.RecalcBounds` also returns immediately when left, top, and height are unchanged, so a later layout pass does not reposition the child.

`TGitDiffView` currently builds the part in `EnsureAppearanceReady`, which runs from `Loaded` via `Application.QueueAsyncCall`. That idle is often before the Manage Repository form is mapped, and it is always before Wayland has a surface for a window that is only now being shown. `EnsureDiffOverviewGutter` then toggles `Visible` and, if a handle exists, calls `RightGutter.RecalcBounds`. That still runs in the same pre-map window. `PagesChange` calls `RefreshOverviewGutter` only when the user changes tabs, so the page that is already selected never gets a second chance.

Windows creates a real child HWND as soon as the handle exists, so the same early path paints. GTK3 and Qt5 on Wayland do not.

## 2. Why Wayland drops the first child

LCL shows children before the toplevel. `TWinControl.DoAllAutoSize` calls `UpdateShowingRecursive(Self, True)` first, and only then `UpdateShowing` on the form itself. A frame `CMShowingChanged` can therefore run while `GetParentForm(Self).Showing` is still false and the toplevel has not been mapped.

On Wayland the toplevel `wl_surface` is created at map, not when the LCL handle is allocated. A native child created before that surface exists is not attached:

- Qt creates a subsurface only when the parent already has a `wl_surface`. If the parent surface is missing, the child platform window is left without one. A later show does not retry that step.
- GTK3 on Wayland likewise has no buffer for an unmapped window. Geometry applied before map is not replayed if the LCL size does not change afterwards.

`HandleAllocated` is true too early on both widgetsets. `scHandleCreated` is the same signal and is not a usable gate. `Showing` on the frame is also too early, because of the children-first pass above.

After map, nothing in SynEdit changes the gutter bounds (the editor already had its LCL size), so `RecalcBounds` no-ops and the child stays at the empty rect `DoResize` left behind. A resize or a tab change can stumble into a later `DoResize` and the strip appears. That matches "not initially displayed".

Creating the child on the next idle after the form's own show returns is late enough: `TWinControl.CMShowingChanged` has called `ShowHide`, so the surface exists, and `QueueAsyncCall` does not run until that stack has returned. Doing the work inside `CMShowingChanged` itself is still too early.

## 3. Fix

One boolean, one deferred method, and a gate on the existing setup. All of it stays in `Source/LazRepositoryTools/GitDiffView.pas`.

`FOverviewMapped` (same private-state prefix as `FAppearanceReady`) means the host form has been mapped and the overview child was created after that. Until it is set, do not call `SetupDiffOverviewGutter`.

### 3.1 Stop creating the child before the form is mapped
Status: complete

Remove the `SetupDiffOverviewGutter` call from the first-time branch of `EnsureAppearanceReady`. Font, colours, and keystrokes stay there. The startup comment stands: do not touch SynEdit gutter surgery from the constructor, and do not call `GetSynEditorSettings` on `DiffEditor`.

`EnsureDiffOverviewGutter` must not create or show the part while `FOverviewMapped` is false. If the part is missing, call the scheduler below and return. Do not toggle `OverviewGutter.Visible` on that path. That toggle is what allocates `FWinControl`'s handle, which is the step that has to move.

Override `CMShowingChanged`. Call `Inherited` first, then if `Showing` schedule the realize method. Also schedule it from `DoDeferredInitAsync` when the frame is already showing, so a frame created on an already-visible form still runs the deferred path.

### 3.2 Create the child on the idle after map
Status: complete

Add `ScheduleOverviewRealize` and `DoRealizeOverviewAsync(Data: PtrInt)`. Schedule with `Application.QueueAsyncCall` on `Self`, which `Destroy` already clears via `Application.RemoveAsyncCalls(Self)`.

`CancelPendingScroll` also calls `RemoveAsyncCalls(Self)`. Do not give the realize callback a separate lifetime that a scroll cancel can drop. `EnsureDiffOverviewGutter` and the load paths that already call it after `CancelPendingScroll` must schedule again when `FOverviewMapped` is still false. `ScheduleOverviewRefresh` must keep its current comment: it must not call `RemoveAsyncCalls`.

`DoRealizeOverviewAsync` creates the child only when all of these hold:

- the frame is alive and not destroying
- `GetParentForm(Self)` is assigned and that form's `Showing` is true (toplevel `ShowHide` has run; the frame's own `Showing` is not the test)
- `DiffEditor.HandleAllocated` and `DiffEditor.ClientHeight > 1`

If the form is not showing yet, or the editor has no handle or no height, re-queue with `Data + 1` up to three times, then stop. The next `CMShowingChanged` or `EnsureDiffOverviewGutter` schedules again. Do not add a `TTimer`. A timer owned by the frame would be written into the host form by the designer.

When the gate passes, if a part already exists it was born too early: free the right-gutter parts the way `SetupDiffOverviewGutter` already does, nil `OverviewGutter` and `DiffOverviewProvider`, then call `SetupDiffOverviewGutter`. That is the whole workaround. `Init` then parents `FWinControl` against a mapped SynEdit, `DoResize` sees a handle, and `BoundsRect` is applied to a real surface.

Set `FOverviewMapped` only after that setup returns with `OverviewGutter` assigned. Reapply `FDisplayedLines` to the new provider when the lines are already loaded. Then set the fixed right-gutter width, call `RecalcBounds` if the handle exists, and invalidate. Do not toggle visibility on this path.

Later calls must not rebuild the part. Once `FOverviewMapped` is set, `EnsureDiffOverviewGutter` only reasserts `AutoSize := False`, width, and `Visible`, then `RecalcBounds`. Keep that for a notebook page whose height was zero on the first map and becomes non-zero when selected. `PagesChange` can keep calling `RefreshOverviewGutter`.

No `{$IFDEF}` for GTK3, Qt5, or Wayland. The same deferral is a no-op delay of one idle on Windows, where the child HWND is valid whenever it is created.
