# Account usage on the status bar

Generated by Lazarus Project Assistant.

Show the active connection's account allowance on the assistant status footer, immediately after the context figure. Only show a figure the service actually returned. Do not estimate, scrape a terminal UI, or call an endpoint this program's credential cannot use.

This is not the per-turn log. `AssistantUsage.pas` and the Settings Usage groups stay as they are: last completed turn, tokens and cost when the response included them. Account allowance is a different question (what is left on the plan or key) and gets its own unit.

## 1. Slim surface

One snapshot, one function type, one registry. No provider class hierarchy, no plugin package, no second status model.

### 1.1 Snapshot and registry
Status: complete

Add `Source/LazAssistantTools/AssistantAccountUsage.pas` and list it in `Packages/LazAssistantTools.lpk`.

The public surface is a record and a function:

- `TAccountUsageSnapshot` has `Known` (Boolean), `ConnectionId`, `Caption`, `Hint`, and `FetchedAt`. `Known` is false when this backend cannot answer. Caption is the short footer text. Hint is the hover detail. Neither field ever holds a key, token, Authorization header, or account email.
- `TAccountUsageQuery` is `Function(Connection: TAssistantConnection; Const RuntimePath, ProfileDir: String; Out Snapshot: TAccountUsageSnapshot; Out ErrorText: String): Boolean`. HTTP backends ignore the two path arguments. Codex uses them so the unit does not reach into the form.
- `RegisterAccountUsageQuery(Const BackendId: String; Query: TAccountUsageQuery)` and `QueryAccountUsage(...)` which looks up `Connection.Backend`. A missing registration returns `Known = False` and does not open a socket. That is the unknown case, not an error.

Parsers are plain functions that take a response body and fill the snapshot, so tests never open a socket or start a process. The unit header states which backends are intentionally unregistered and why (section 2.3).

If the Codex process wrapper makes this file hard to follow, move only that wrapper to `AssistantCodexUsage.pas`. Do not split the snapshot type out on its own.

### 1.2 Leave turn usage alone
Status: complete

Do not extend `TAssistantUsageRecord`, `usage.jsonl`, or the Settings Usage labels for this. Those records are one turn. A quota query must not append a usage line, and a missing quota must not change the "did not report usage" sentence on the connection page.

## 2. What each service can answer

Register a query only where a documented call already fits the credential this program holds. Everything else stays unregistered and the label stays hidden.

### 2.1 OpenRouter key balance
Status: not started

Register `openai-compatible`. The query returns unknown immediately unless `ApiBase` is `AssistantOpenRouterApiBase` (the OpenRouter preset). A custom base has no shared usage URL; do not guess one.

Call `GET {ApiBase}/key` with the same bearer header `TAssistantCompatibleClient` already builds. Use the injected GET already on that client (`CreateForTransport`) so a fixture answers without a socket. Do not call `GET /api/v1/credits`: that route wants a provisioning key, and a normal inference key is what this connection stores.

Read `data.limit_remaining` when it is a number. Caption is `Left` plus the amount, for example `Left $18.20`. Hint adds `usage_daily` when present, and the fetch time. If `limit_remaining` is null and `data.free_model_daily_requests.remaining` is a number, caption is `Free N left`. If the key is unlimited and there is no free-request counter, return unknown and hide the label — "no cap" is not a usage figure. A non-200 or a body without those fields is a failed query, not a zero balance.

### 2.2 Codex rate limits when idle
Status: not started

Register `codex`. Read `account/rateLimits/read` from the Codex app-server (empty params). That is the same app-server the handshake already speaks; the documented result has `rateLimits.primary` and `rateLimits.secondary`, each with `usedPercent`, `windowDurationMins`, and `resetsAt`. Prefer the `codex` entry of `rateLimitsByLimitId` when that object is present, otherwise `rateLimits`.

Do not send this request on the live turn client. `TAssistantCodexClient.HandleFrame` forwards every numeric-id reply to the handshake, and the handshake drops ids other than initialize, account read, and login. A quota reply on that channel would vanish, and a second app-server against the same profile during a turn can fight the turn's login refresh.

Query only while that connection is idle (not sending, not in a plan run, not reviewing). Use a short-lived app-server, the same bounds as `TAssistantCodexAccount`: no login start, no model turn, cancel on connection change, hard deadline, then disconnect. Pass the connection's executable and `TAssistantConnections.ProfileDir`. If the server is not signed in, return unknown; the footer already says `Not signed in`.

Caption is used percent, matching how context is read, with a window tag derived from `windowDurationMins` (`5h` for 300, `7d` for 10080, otherwise the minute count). Show the primary window, and the secondary in the same caption only when it fits on one short line, for example `5h 25% · 7d 7%`. Hint states that the numbers are used, plus each reset time. If `rateLimitReachedType` is set, caption is `Limit` and the hint names the window. Do not read or display `account/read` email.

Ignore `account/rateLimits/updated` pushes in this pass. The handshake currently discards that notification. Polling while idle is enough.

### 2.3 Leave Grok, Claude, and custom endpoints quiet
Status: not started

Do not register `grok`, `claude`, or a custom `openai-compatible` base.

- Grok here is the desktop OAuth token (`grok-cli:access` / `api:access`). xAI's billing routes need a team id and a management credential this program does not store. Per-turn `usage` is already logged and is not an account balance. Do not call the X API credit endpoint, and do not invent rate-limit header names. `AssistantHttps` does not return response headers today; do not widen it for an undocumented header.
- Claude is the `claude` program. `claude -p --output-format json` reports session cost, which the turn log already covers. Plan quota is an interactive `/usage` screen. Do not drive a PTY, do not read Claude's credential files, and do not call an OAuth usage URL that is not part of this program's contract.
- A custom OpenAI-compatible base has no standard balance route.

If a later official call appears for one of these, it is a new query function behind the same registry. No footer or form change should be required.

## 3. Footer

The context figure stays where it is. Account usage is the next label to its right, and only when a snapshot is known.

### 3.1 Label after the context figure
Status: not started

`TStatusFooterFrame` (`Source/LazWorkflowCommon/StatusFooterFrame.pas` and `.lfm`) currently centres `ModelLabel` and places `CentreLabel` one scaled 16px gap to its right. Add `UsageLabel` in that host, after `CentreLabel`, with the same gap.

- Stream the label in the frame `.lfm` and the unnamed first section of the frame class. No `F` prefix. Empty caption hides it (`Visible = False`, width 0) so repository windows that share this frame do not grow a blank slot.
- `SetUsageText` / `SetUsageHint`. No click handler and no hand cursor. Context keeps the breakdown click; this label is hover-only.
- `LayoutCentrePair` must include the usage label's width in the right-hand clamp, so a long caption cannot pull the model line off centre or under the right-hand status. When the label is hidden, layout matches today.

`UpdateStatusFooter` in `ProjectAssistantForm.pas` keeps building `Context N%` (or the Codex token estimate) for `SetCentreText`. It then applies the latest snapshot for `FActiveConnectionId` only. A snapshot for another id is ignored. Unknown or a different connection clears the usage label. Do not append the account figure to the context caption.

### 3.2 Refresh off the IDE thread
Status: not started

The footer read is a locked snapshot. The query itself never runs inside `UpdateStatusFooter` or on the IDE thread.

One worker at a time. A late result whose connection id is no longer active is discarded. On failure, keep a known snapshot for that same connection if it is under 15 minutes old, and put the failure in the hint only. Never replace a figure with an error caption. Log one warning line and do not include the key or the request URL's credentials.

Start a query when:

- the active connection changes (clear the label first)
- a turn completes and the backend is registered
- the form is visible, the connection is idle, and the last attempt for this connection is older than 3 minutes

Skip Codex while a turn, plan run, or review owns that profile. An OpenRouter `GET /key` may run during a turn; it does not share the chat socket.

Use a timer created with `Create(Nil)`, freed with `FreeAndNil` in the form destructor, so the designer does not stream it into `ProjectAssistantForm.lfm`. Do not reuse `ElapsedTimer` (250 ms send clock). A one-second poll that only starts a query when one of the conditions above is true is enough.
