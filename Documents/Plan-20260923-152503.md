# Compact configuration

Generated by Lazarus Project Assistant.

Replace the current mix of XML, INI, JSON, TOML, hashed test files, and a parallel session file with two JSON documents. IDE-wide settings live in one file under the Lazarus primary config directory. Per-target settings live in the existing `.assistant/config.json`. Legacy filenames are not read and are not migrated. A missing file means defaults; sign-in, connections, spell options, graph font, and test commands are entered again.

Git’s own files stay Git’s: `.gitignore`, local and global Git config, and `.git/description`. `AGENTS.md` and `SKILL.md` stay user content. Conversation history stays `conversation.jsonl`. Those are not settings.

Either optional package must still install and run without the other. `LazWorkflowCommon` is the only shared requirement. Do not add a `RequiredPkg` between `LazRepositoryTools`, `LazAssistantTools`, and `LazStyledText`. Common must not use either optional package. The existing `SuggestCommitMessageFunc` hook stays a nil function pointer when the Assistant is not installed; Suggest stays disabled with the current message.

## 1. Owned files

### 1.1 IDE document
Status: complete

Add `WorkflowSettings` in `LazWorkflowCommon`. It loads and saves `<primary-config>/LazWorkflow.json` and nothing else. Write via a temporary file and rename. On Unix, mode `0600`. If the file is missing or invalid, use defaults and do not fall back to `LazAssistantTools.xml`, `LazGrokChat.xml`, `LazRepositoryTools.xml`, `LazGitManager.xml`, `LazWorkflowSpell.xml`, `assistant-connections.ini`, or `assistant-backend.ini`.

Common owns the file and the `spell` section only: `engine`, `language`, `library`, `dictionary_directory`, and `personal_words` (a string array). No separate dictionary path and no `LazWorkflowPersonal.dic` as a source of truth. If an engine needs a word-list file, write a derived cache from this array at apply time. Common does not declare connection, OAuth, or graph-font types, and it does not create Codex directories or `.assistant/` folders.

Expose a section read/write that replaces one named object and preserves every other key, including keys this package does not understand. A save from Repository-only must leave an `assistant` object untouched, and a save from Assistant-only must leave a `repository` object untouched. A missing section is that package’s defaults, not an error.

- `assistant`, written only by `LazAssistantTools`: `include_ide_context`, `auto_new_chat_at_limit`, `active_connection`, and `connections`. Each connection has `id`, `name`, `backend` (`grok` or `codex`), `model`, `thinking`, and `approval` (`ask`, `auto`, `always`). Grok also has `api_base`, `skill`, and `oauth` (access token, refresh token, token type, scope, expiry). Codex also has `runtime` (executable path only). The built-in `grok` connection cannot be removed. No API key field.
- `repository`, written only by `LazRepositoryTools`: `auto_refresh`, `interval_sec` (2–3600), `graph_font_name`, `graph_font_size` (6–24).

`SpellCheckerConfig` becomes the spell view. `GitConfig` and `AssistantConfig` / `AssistantConnections` become the section views in their own packages. They stop calling `GetIDEConfigStorage` and `TIniFile` for settings.

### 1.2 Target document
Status: complete

Keep one settings file per work target: `<store>/.assistant/config.json`. The store is `<working-root>/.assistant/` for the open project, or `<working-root>/.assistant/targets/package-<relative-hash>/` for a package. Do not walk parent directories, and do not look in `Source/` or beside the project file. This file is Assistant-only. Repository never reads or writes it, so a Repository-only install creates no `.assistant` store.

Extend the existing keys (`show_thinking`, `show_tool_use`, `active_mode`, `plan_file`) with a `tests` object: `enabled`, `executable`, `arguments`, `timeout_seconds`, `report_format`, `minimum_tests`. Same validation as today. Delete `assistant-tests/<sha1>.ini`. A moved project keeps its test command because it now sits with the target, not under a hash of the absolute path.

### 1.3 Derived Codex profile
Status: complete

Codex still needs a directory because the runtime owns `CODEX_HOME`. That directory is not a second settings store. Every Codex connection, including the first, uses `<primary-config>/codex/<connection-id>/`. Delete the `assistant-codex-preview` special case. Only the Assistant creates this directory.

`PrepareCodexProfile` rewrites `config.toml` from the same fixed policy on every launch (ChatGPT login, on-request approval, read-only sandbox, web search and shell tools off). Model, effort, and approval stay in the `assistant` section and are sent on the turn. Do not copy runtime credentials into the JSON. Removing a connection removes its definition only; deleting the profile directory is a separate explicit action, not part of save.
