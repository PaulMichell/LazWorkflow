# Revised Comms Plan

Generated by Lazarus Project Assistant.

The phone still falls behind a live turn, and the last host change made that worse. This plan replaces push-everything with one model-independent mirror: an epoch, a cursor, a small live patch, and a resume after a drop. The IDE remains the only process that talks to a model. The phone keeps a read-only copy of conversations it has already synced, so review works with the host stopped.

This file previously held the App Menu drawer plan. That work is not part of this plan. Do not build the drawer here.

The listen thread already exists. Do not add another socket thread, and do not read `TProjectAssistantForm` off the IDE thread. A long IDE-thread tool can still delay the next patch until that tool returns. The client must keep the last good screen and resume, not hammer the host.

LazAssistantTools must still compile and run with LazAssistantMonitor absent. The monitor package may call the form. The assistant package must not name a monitor unit.

## 1. Why the current path fails

The desktop trace is already model-independent. Codex, Claude, and Grok all land in `FTrace` and `FLiveContent` on `TProjectAssistantForm`. The wire is not. Grok calls `AssistantSessionObserve(asnTranscript)` from `StreamToken`. Codex and Claude do not. `PublishLiveMonitorTurn` on the 250 ms elapsed timer was added to cover that gap. It still ships a full live transcript, and the timer also sends `asnStatus` on every tick while a turn is sending.

`TAssistantMonitorBridge.Hear` queues every notice onto the IDE thread. `PushTranscript` calls `FillMonitorTurn`, copies every block, and `NextTranscriptRevision` advances even when the phone already has those blocks. `TMonitorSession` then holds that frame for `MonitorCoalesceWindowMs` (100) and refuses to enqueue it when `FPendingSends` is at `MonitorOutboundQueueLimit` (32). The comment in `FlushTranscriptLocked` records the result: the phone stays on the last busy status. The left label is `connectionLabel` in `MonitorViewModel.kt`. It prints `busy` whenever the link is live and the last view has `busy`, `sending`, or `planRunning`. Those flags ride on status frames, which still get out while the body does not.

Recovery made this heavier. After 15 s with no host progress the phone sends `Refresh` (`BusyStallMs`, `busyStallRefresh`). That command builds a snapshot of up to 30 turns on the IDE thread. `SweepCommands` now cancels an unclaimed command after 5 s and answers `host_busy`. A stalled view therefore gets an error instead of a snapshot, and the conversation does not move. More full transcripts plus a recovery path that fails is why the stall is worse after that fix.

Continuity is also the wrong key. The host resets `FTranscriptRevision` for a new session. The phone compares `liveRevision` and turn index. A reconnect can look frozen while ping/pong still reports live. The offline file is one `offline-cache.json` of the last screen, written from `onCleared` and a remember path. It is not a library of conversations, and it does not survive as a review list.

## 2. Wire contract

Catalogue version is `MonitorCatalogueVersion` in `AssistantMonitorCodec.pas`. It is 2. Frames are length-prefixed JSON, payload cap `MonitorMaxPayloadBytes` (262144) in `AssistantMonitorFrames.pas`. Ping, pong, send, steer, stop, approval, and `image_get` stay. The live path stops being a full `transcript` plus a separate status tick.

### 2.1 Catalogue version 2

Status: complete

Raise `MonitorCatalogueVersion` to 2 in `AssistantMonitorCodec.pas` and in the Kotlin protocol module together. A version mismatch stays a `rejected` or `error` with reason `protocol`. Do not half-parse a v1 body as a v2 patch.

Add three host messages and one client message. Names are exact:

- `resume`. Client to host. Payload fields `epoch` (string) and `cursor` (int64). This is not a user command.
- `patch`. Host to client. One committed live change. Fields are in item 2.2.
- `catchup`. Host to client. Either `mode = snapshot` plus the existing snapshot object and the cursor it represents, or `mode = events` plus an ordered list of patches the ring still holds. One message kind, two modes, so the client has one resume result.
- `conversation_closed`. Host to client. Fields `epoch`, `cursor`, `conversation_id`, `title`. Sent before the host mints the next epoch, so the phone can file the copy it already has.

Keep `snapshot`, `transcript`, `status`, `plan`, and `turn_data` encoders compiling so existing tests still name them. The live pump must not send `transcript` or `status` for ordinary growth. `plan` remains the plan-list message. `turn_data` remains the on-demand history body.

Codec tests in `Tests/AssistantMonitorCodecTest.lpr` and the Kotlin protocol tests must round-trip each new message, including a patch that does not fit in one frame. A patch over the cap is `part` / `part_count` with the same `cursor`. A missing part must not decode as success.

### 2.2 Epoch, cursor, and conversation id

Status: complete

An epoch is a new hex string. Mint it when the bridge attaches to a project conversation, and again when the project changes, `StartNewConversation` runs, or an archive is activated. Put `epoch` and `cursor` on `hello_ok`, `patch`, `catchup`, and `conversation_closed`.

`cursor` is an int64 inside one epoch. Zero means the client has applied nothing. The host assigns the next cursor only when it commits a patch, a plan change, a closed turn, or a catchup snapshot. Resending the same committed patch uses the same cursor. A newer unsent patch may replace an older unsent patch, but a cursor already handed to the carrier must not be reused for different bytes.

`conversation_id` is `current` for the open `conversation.jsonl`, or the archive id `TAssistantConversationStore` already uses (`conversation-YYYYMMDDTHHMMSSMMM`). `project_root` is the existing target root string. `title` is `HistoryTitleForCurrent` when that is non-empty, otherwise the first prompt preview. These three fields travel on `hello_ok` and `catchup`, and `conversation_id` plus `title` travel on `conversation_closed`.

The phone must not treat turn index or `liveRevision` as continuity. Same epoch and a higher cursor is progress. Same epoch and a lower or equal cursor is a duplicate and is ignored. A different epoch is a new host generation. Keep the previous conversation on screen until the new epoch's catchup arrives.

## 3. Host mirror

The mirror is in-memory on the monitor session. Do not add a second conversation file under the project `.assistant` directory. Closed turns stay in the existing JSONL. The ring exists only so a reconnect can catch up without reading the form for every lost frame.

### 3.1 One dirty pump

Status: complete

Add `TouchAssistantMirror` to `AssistantSessionObserve.pas`. It increments a counter under the existing lock and returns. A nil listener does not matter: the counter moves either way, and a missing monitor never observes it. Do not build JSON and do not call `TThread.Queue` from this procedure.

Call `TouchAssistantMirror` from the form paths that already change what the phone shows: `ApplyLiveThinkingAndAnswer`, `HandleTraceEvent`, `SetSending`, `SetBuildStatusFeedback`, `RefreshBuildTodos`, and the end of `FinishAssistantReply`. Do not call it from the provider poll itself. Codex, Claude, and Grok already reach those form paths. The monitor unit must not name a provider.

Delete the live use of `PublishLiveMonitorTurn`. The elapsed timer must not call `AssistantSessionObserve(asnTranscript)` or `asnStatus` merely because 250 ms passed. `StreamToken` must not observe `asnTranscript` on every token. Those observes are what queued a full copy onto the IDE thread.

In `AssistantMonitorBridge.pas`, own a `TTimer` created with `Create(Nil)`, not streamed, interval 150 ms, enabled only while a session is attached. Each tick reads the mirror counter. If it equals the last pumped value, return. If it differs, build at most one live patch and, when the plan rows changed, one plan message. Then store the counter. A burst of tokens between ticks becomes one patch.

The pump runs on the IDE thread because it reads the form. If that thread is inside a tool, the timer waits. That is accepted. Do not call `CheckSynchronize` from the tool or from the listen thread.

### 3.2 Live patch, not a full transcript

Status: complete

`patch` carries `epoch`, `cursor`, `turn_index`, `turn_id`, and only the blocks whose revision or presence changed since the previous committed patch. Each block keeps the fields the phone already draws: kind, block id, title, tool name, tool id, body, running, ok, duration. Also include the flag set the status bar needs: `busy`, `sending`, `plan_running`, `phase`, `can_send`, `can_steer`, `can_stop`, `elapsed_ms`. Do not include the stored-turn array. Do not include a block whose body, title, running flag, and ok flag are unchanged.

The host keeps the last sent block revisions in the bridge, not in the form. The first patch after an epoch sends every current live block once.

If the dirty blocks do not fit in `MonitorMaxPayloadBytes`, split that one cursor into parts. The session's live lane holds the part set. A newer patch replaces an unsent part set. It does not append another full transcript behind it.

`elapsed_ms` is informational. The phone ticks the clock locally from the last value. The pump must not send a patch when the only change is elapsed time.

A plan-row change is the existing `plan` message with the same epoch and a new cursor. It must not also force a live transcript of every block.

### 3.3 Resume and catchup

Status: complete

On `hello_ok` the client sends `resume` with the epoch and cursor it last committed, or epoch empty and cursor 0 if it has none. The host handles `resume` on the session, then the bridge.

If the epoch matches and every cursor after the client's cursor is still in the ring, `catchup` mode is `events` and the body is those patches in order. Ring capacity is 256 committed records, or fewer if a record would make the ring exceed 2 MiB of JSON. Dropping the oldest record is allowed. State the drop in the session so a later resume of a discarded cursor does not pretend the events are complete.

If the epoch differs, or the cursor is below the oldest ring record, or the cursor is unknown, `catchup` mode is `snapshot`. Reuse `PushSnapshot`'s fill of view, live turn, stored turns (cap `MonitorSnapshotTurnCap`, 30), plan rows, and approval. Add `epoch`, `cursor`, `conversation_id`, `project_root`, and `title`. After that snapshot the client's cursor becomes the snapshot cursor. Further live changes are patches with higher cursors.

`conversation_closed` is sent, and the closed conversation's last cursor is committed, before the new epoch is minted. The phone files the screen it has under the closed id. Then the empty conversation is a new epoch at cursor 0.

### 3.4 Recovery is not host_busy

Status: complete

Split the session outbound queue into three lanes. Control carries ping, pong, bye, error, approval, and command results. Live carries the current unsent patch part-set only. Bulk carries catchup, snapshot, plan, and image bytes.

Control is never dropped to make room for live or bulk. Live replacement does not wait for a full bulk lane. Bulk may wait. The old single cap of 32 on `FPendingSends` must not apply to a live patch. `FlushTranscriptLocked`'s "keep the frame or the phone stays busy" path goes away because the live lane no longer shares that array.

`SweepCommands` still answers `host_busy` for a user command the IDE has not claimed in `MonitorCommandWaitMs` (5000): send, steer, stop, mode, plan actions, and the old `refresh`. It must not cancel or answer `host_busy` for `resume`. Resume stays queued until the IDE thread can fill the catchup. The listen thread still must not `RTLEventWaitFor` inside `ServiceIdle`.

The phone must stop sending `Refresh` as a stall probe. Item 4.2 removes that call. The host may keep the `refresh` decoder so an old binary gets `host_busy` instead of a 30-turn snapshot on the IDE thread.

## 4. Phone sync

The Kotlin reducer stays a pure function in the protocol or `MonitorCoordinator` layer so JUnit can run it without Android. `LinkPhase.Live` means the socket is up. It must not be used as proof that the cursor is current.

### 4.1 Reducer on epoch and cursor

Status: complete

Replace `liveRevision` continuity in `applyTranscript` with epoch plus cursor. Apply a patch only when `epoch` equals the committed epoch and `cursor` is the next expected cursor, or the cursor equals the committed cursor and the part set was incomplete. Assemble parts by `part` number. Advance the committed cursor only when every part of that cursor is present. A lower cursor in the same epoch is ignored. A gap (cursor greater than committed + 1) does not guess the missing body. It sends `resume` once.

On a new epoch, do not clear the on-screen conversation and do not clear the cache. Set a catching-up flag. When `catchup` arrives, replace the open conversation if `conversation_id` and `project_root` match the cache key, or switch the open key if the host is now on another conversation. Then clear the catching-up flag.

`hostTranscriptIdle` must not be the only way the left label leaves `busy`. The patch flags are authoritative. When `busy`, `sending`, and `plan_running` are all false, `connectionLabel` returns `live` even if no later status frame arrives. A lost final status was the stuck-busy bug.

`conversation_closed` writes the current screen into the cache under the given id and title, then waits for the new epoch. It does not delete the closed file.

### 4.2 Stop the stall refresh

Status: not started

Remove `busyStallRefresh` and the `Refresh` send in `MonitorCoordinator.kt`. A gap is: link live, host flags say busy or a catchup is outstanding, and no patch, catchup, or plan message has arrived for 5 s. Send one `resume` with the committed epoch and cursor. Do not send another until a host message arrives or the socket drops. Do not send `Refresh`.

On socket close, keep turns, live blocks, plan rows, and the draft. The banner may say reconnecting. Do not reset the committed cursor. The existing `LinkGraceMs` behaviour can stay. Reconnect sends `resume` after `hello_ok`, not a full snapshot request on a timer.

Ping and pong stay. A dead session still uses the host's `MonitorDeadSessionMs` (45000) and the phone's existing read timeout. A live socket with a stale cursor is a resume, not a reconnect.

### 4.3 Local elapsed clock

Status: not started

The right-hand activity time ticks on the phone from the last `elapsed_ms` and the local time that patch was applied. Do not wait for a host frame to advance the seconds. A new patch replaces the base. When the patch says the turn is idle, stop the tick. This removes the need for a 250 ms status frame whose only change is the clock.

## 5. Offline conversations

The host store remains the authority while connected. The phone cache is a replica for review. Do not upload it. Do not add a host command that writes the cache back. Remote send, steer, and plan actions stay disabled while `disconnected` is true, as they are today.

### 5.1 Cache directory

Status: not started

Replace the single `offline-cache.json` written by `OfflineStore` with a directory under the app files dir, `monitor-cache/`. `index.json` lists entries. Each entry has host fingerprint, `project_root`, `conversation_id`, title, updated time, turn count, and the file name. One JSON file per conversation holds turns, the live blob, plan rows, and the draft. Image files already decoded stay beside that conversation, named by image id.

Debounce saves by 1 s after a committed cursor, and save again on socket close and in `onCleared`. A failed write must not drop the live session, which is already the rule in `rememberDisplayed`.

Keep at most 20 conversations per fingerprint. When a 21st is filed, delete the oldest conversation file and its images. Cap image bytes at 32 MiB per fingerprint. Evict oldest image files first. A missing image stays a placeholder. Do not fetch images while disconnected.

Forget pairing deletes only the directory entries for that fingerprint. Other hosts stay.

Load the index at process start. If the index is unreadable, start empty and do not crash. Do not keep writing the old `offline-cache.json`. Delete that file once on first successful directory save so two copies cannot diverge.

### 5.2 File a closed conversation

Status: not started

On `conversation_closed`, write the on-screen turns under that `conversation_id` and title before applying the new epoch. On each committed patch for `current`, update the `current` file for that fingerprint and project root. Switching project root on the host is a new cache key, not an overwrite of the previous project.

The index row's title updates when the host title changes. Prompt preview of the first user block is the fallback when title is empty.

### 5.3 Review while disconnected

Status: not started

While the link is not live, the conversation page shows the open cached conversation, including its live blob if the drop happened mid-turn. Add a list control that is available only while disconnected: a text button "Cached" on the conversation page header row, opening a dialog of the index rows for the last fingerprint. Choosing a row loads that file into the conversation page and does not open a socket. Back returns to the list. No drawer, no mode change, no plan run.

While the link is live, that button is hidden. The host's open conversation is the page. Cached rows remain on disk for the next disconnect.

The list shows title, project display (the last path segment of `project_root`), and updated time. Empty index shows the existing offline banner and no rows. Do not require the App Menu drawer for this list.

## 6. Proof

### 6.1 Host tests

Status: not started

Extend `Tests/AssistantMonitorCodecTest.lpr` for version 2, patch parts, and `conversation_closed`. Extend `Tests/AssistantMonitorSessionTest.lpr` for the lanes and resume. Required cases:

- A full bulk lane still accepts a live patch, and that patch replaces an older unsent patch rather than appending.
- A control ping is sent while both other lanes are at their caps.
- Resume of a cursor still in the ring returns events and does not call the form snapshot fill.
- Resume of a discarded cursor returns one snapshot and the snapshot cursor.
- Resume is not completed with `host_busy` when the IDE thread has not yet claimed it.
- A user send that is still unclaimed at 5 s still returns `host_busy`.

The assistant package test that links without LazAssistantMonitor must still pass. `TouchAssistantMirror` with no listener must not raise and must not require the monitor unit.

### 6.2 Phone tests

Status: not started

Add JUnit tests in the protocol module, not instrumented Android tests. Required cases:

- A patch with the next cursor updates one block and leaves the others.
- An incomplete part set does not advance the cursor. The completed set does.
- A lower cursor in the same epoch does not change the screen.
- A new epoch leaves the previous turns visible until catchup, then replaces them.
- `conversation_closed` followed by a new epoch files the closed id and shows the empty conversation only after catchup.
- Two saved conversations can be loaded with the socket stub disconnected. Forget pairing removes one fingerprint and leaves the other.

### 6.3 Design note

Status: not started

Add a short section to `Documents/Assistant Monitor Design.md` that states the v2 rule: live sync is epoch, cursor, and patch; resume replaces stall `Refresh`; the phone cache is a read-only replica keyed by fingerprint, project root, and conversation id. Mark the old lines that say the phone has no conversation store as overridden for this replica only. Do not reopen the relay, remote image upload, or the drawer in that note.
