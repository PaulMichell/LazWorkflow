# LazAssistantMonitor review

Generated by Lazarus Project Assistant.

Review of `Source/LazAssistantMonitor` against catalogue 3 (`Documents/MonitorProtocolV3.md`) and the phone in `Source/KotlinMonitorApp`. Findings below are cited from the current source. The suite was not run for this review. `Source/LazAssistantMonitor/Backup` is gitignored and is not part of the package; leave it alone.

## 1. Bugs

In severity order. Each item is a defect, not a style note.

### 1.1 Do not re-enter the session lock on ack
Status: complete

`TMonitorSession.InboundFrame` holds `FLock` and calls `HandleLocked`. For `type` `ack` that calls `NoteLogAck`, which calls `LockSession` again, then `FillLogLane`, which locks again. `TRTLCriticalSection` is not recursive on Linux, so the first ack deadlocks the link thread while it still owns the session lock. The next IDE publish then waits on that same lock, so the IDE hangs. Windows would not deadlock; the nested `FillLogLane` unlock would still drop the outer hold one level early if the mutex were recursive.

The phone sends these frames: `SyncApplier.AckPacer` emits `SyncEffect.Ack`, and `MonitorViewModel` writes `encodeAck`. They arrive on the link thread through `DeliverFrame` → `InboundFrame`. No session test delivers an ack through that handler, which is why this survived.

Fix: update `FPhoneAcked` in `HandleLocked` under the lock already held. Call `FMirror.NoteAck` and `FOutbox.Acknowledge` either before taking the session lock or after releasing it, and call `FillLogLane` only after `InboundFrame` has unlocked. Do not add a recursive mutex.

Acceptance: a session test that delivers an ack through the carrier frame handler must return, advance the ack, and still accept a later command. Run `AssistantMonitorSessionTest` and `AssistantMonitorLockupTest`.

### 1.2 Honour the ack rules in protocol section 5.4
Status: complete

`TMonitorMirror.NoteAck` ignores a `stream_id` that is not the open stream. `NoteLogAck` still calls `FOutbox.Acknowledge(Seq)` and, when `Seq` is greater, stores it in `FPhoneAcked`. An ack from the previous conversation, whose sequence is higher than the new stream's head, drops the new stream's log frames. The protocol also says an ack beyond the sent head is `error` reason `protocol` and does not move credit. `NoteLogAck` does neither check.

Do this in the same change as 1.1, after the lock is no longer re-entered. Ignore a stale `stream_id`. If `Seq` is above `FMirror.Head`, queue `error` and leave `FPhoneAcked` and the outbox where they are.

Acceptance: two session checks, one stale stream and one seq past the head. The open stream's log frames stay queued in both.

### 1.3 Refuse a codeless pair that omits the fingerprint
Status: not started

`HandlePair`, when `PairCodeRequired` is off and the phone sends no code, refuses only when both fingerprints are non-empty and differ. An empty `fingerprint` skips the check. With the pairing code off, that check is the only proof the phone is talking to this host. A peer in the middle can pair by omitting the field.

When the host fingerprint is known, require the phone's fingerprint and compare it, including on the no-code path. Keep the existing rule that a typed code is still checked, and that loopback may pair with no code armed when the setting is on.

Acceptance: extend `TestLoopbackPairingPolicy` (or the codeless pair checks beside it) so a non-loopback pair with an empty fingerprint is `fingerprint` when the host fingerprint is set, and a matching fingerprint still pairs.

### 1.4 Answer a catalogue mismatch in the client's version
Status: not started

`TryDecodeMonitorEnvelope` returns false when `v` is not 3, and `HandleLocked` then calls `RejectLocked('protocol')`. That encodes `rejected` with `v: 3` (`EncodeMonitorEnvelope` always writes `MonitorCatalogueVersion`). Protocol section 3 says this one reply uses the client's envelope version so an older app can read it and show the update message. An older phone cannot decode a version-3 reject.

On a version mismatch, read `v` before failing the decode and encode that one `rejected` with the client's version, host version 3, and the client's version in the payload. Do not accept any other catalogue-2 message.

Acceptance: `AssistantMonitorCodecTest` or `AssistantMonitorSessionTest` feeds a `v: 2` hello and checks the reject envelope is version 2, reason `protocol`, and the socket is closed.

### 1.5 Close the link when a chunked state value cannot be framed
Status: not started

`PublishState` builds chunks and, if `EncodeMonitorFrameBytes` fails, increments `FFramesDropped` and returns. `QueueFrame` closes the link for the same failure. The phone keeps the previous value for that key and is not told. A later resume can also republish the same value and drop it again.

On any failed chunk, call `CloseToListening`, as the single-frame path does. Do not leave a partial `ReplaceState` queued.

Acceptance: a session test whose state value cannot be framed (or a forced encode failure, if the test seam already exists) ends the link and does not leave that key in the outbox.

## 2. Dead or obsolete code

Only paths with no production caller. Do not delete catalogue kind names that an incoming frame can still carry.

### 2.1 Remove the unused session send helpers
Status: not started

`EnqueueAccepted`, `StorePlanSend` and `ReplacePlanFrames` are public on `TMonitorSession` and have no caller in `Source/` or `Tests/`. `StorePlanFrames` stays; it is used by the plan path. Delete the three methods and their declarations.

Acceptance: the package still compiles. `AssistantMonitorSessionTest` still passes.

### 2.2 Stop admitting work_on_plan as a turn
Status: not started

The phone app does not call `encodeWorkOnPlan`. `DispatchCommand` always fails `mmkWorkOnPlan` with "Use Run Plan." `HandleCommand` still lists it in `BusyKinds`, so `EnterBusy` sets `FSendPending` until the IDE thread's `NoteCommandRejected` clears it. For that gap every other command looks busy.

Remove it from `BusyKinds` and from `LongRunningCommand`. Keep the kind in the catalogue so an old frame is still decoded. The bridge may keep the explicit error, or return the ordinary unknown-command error. Do not delete `encodeWorkOnPlan` in this package; it is phone protocol code.

Acceptance: a session test that delivers `work_on_plan` does not set the send-pending flag, and a following `send` is still admitted.

## 3. Simplifications

### 3.1 One queue path
Status: not started

`QueueFrame` already places a frame when the caller names the lane. `QueueSend` parses the JSON again with `MonitorSyncClassify`, and if that fails parses it a third time in `HostLane`. `MonitorSyncEventSeq` then searches for the text `"seq":`, which misses fpjson's `"seq" :` and can match a `seq` inside a string. The session header says known producers already pass the lane.

Route `TryQueueHostJson`, the echo in `HandleLocked`, and `EnqueueAccepted`'s only caller through `QueueFrame` or a thin wrapper that classifies once and passes the lane and sequence. Delete `HostLane`, `THostLane` and `MonitorSyncEventSeq` if nothing else calls them. Keep the bye special case (a bye that cannot be queued still closes).

Acceptance: `AssistantMonitorCodecTest` and `AssistantMonitorSessionTest` pass. A spaced `"seq" :` event, if any test still sends one through the unknown-origin path, is queued under its real sequence.

### 3.2 One resume-status record
Status: not started

`HandleResume` and the observation branch of `FillLogLane` each fill a `TMonitorSyncStatus` from `FHostFlags` by hand. The observation branch omits `PlanRunning`, `CanChangeMode` and the approval fields that `HandleResume` sets. Copy one function, used by both, so a baseline pushed when the mirror becomes ready carries the same status as the resume that asked for it.

Acceptance: a session test that resumes before the mirror is observed, then observes, gets a resume answer whose status matches the host flags, including plan-running and approval.

## 4. Performance

### 4.1 Do not lock the session on an idle poll
Status: not started

The link thread calls `FillLogLane` from `TakeOutboundFrameWithLane` and again from `PrepareOutboundCount` on every pass. The "nothing changed" check (`LogFillSeen`, head, ack, queued seq) sits inside `LockSession`. An idle live link still takes the session lock twice per poll, and that lock is the same one the IDE thread needs to publish.

Keep the fill, but skip the lock when an atomic generation says the head, the ack and the queued sequence have not moved since the last fill. The generation moves only under the session lock. `PullPlanSlice` already returns immediately when no fetch is ready; leave that as it is.

Acceptance: `AssistantMonitorLockupTest` still passes. A debug counter, or the existing outbox lock metric style, is enough to show an idle poll does not enter `FLock`. Do not leave the counter in a release build unless it is already behind `MONITOR_OUTBOX_METRICS`.

### 4.2 Copy the log tail once
Status: not started

`MonitorSyncFill` calls `Mirror.TryEvent` once per sequence. `TryEvent` takes and releases the mirror lock and binary-searches for every event. A resume that replays a long tail does that for each event, on the link thread, while `FillLogLane` also holds the session lock.

Add a mirror call that, under one lock, copies the events after `QueuedSeq` up to the credit window (or the head). `MonitorSyncFill` then frames that copy without locking per event. Do not hold the session lock across the frame encode if the copy is already private.

Acceptance: `AssistantMonitorMirrorTest` and `AssistantMonitorGrainTest` still pass. The grain timing check (20 000 small events) must not get slower.

### 4.3 Do not parse a state value just to see that it is JSON
Status: not started

`PublishState` calls `StateValueIsJson`, which runs `GetJSON` on every value, then `MonitorSyncStateFrames` builds the envelope from the same text. Status is published on the IDE thread several times a second while a turn runs. The writers in `AssistantMonitorSync` already return one JSON object.

Trust a value that those writers built. Keep the parse only for a value that did not come from them, or drop the parse and let `EncodeMonitorFrameBytes` reject a broken value by closing, which 1.5 already requires for a frame that cannot be encoded. Do not parse twice on the status path.

Acceptance: with `MONITOR_COUNT_PARSES` defined, one status publish does not call `GetJSON` on the value. `AssistantMonitorCodecTest` still passes.
